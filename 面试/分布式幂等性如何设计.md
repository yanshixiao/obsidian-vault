### 分布式幂等性设计方案

#### 1. **核心概念**
• **幂等性定义**：多次执行同一操作与一次执行结果一致。
• **适用场景**：支付、订单创建、库存扣减等关键操作。

#### 2. **实现方案**
**方案一：唯一请求标识（Token/ID）**
• **流程**：
  1. **生成唯一ID**：客户端发起请求时生成全局唯一ID（如UUID或雪花算法生成的ID）。
  2. **检查ID状态**：服务端接收到请求后，先查询存储系统（如Redis或数据库）判断该ID是否已处理。
  3. **处理请求**：
     ◦ **未处理**：执行业务逻辑，将ID标记为已处理（设置过期时间）。
     ◦ **已处理**：直接返回之前的结果。
• **存储选择**：
  • **Redis**：使用 `SET key ID NX EX 3600`（原子性操作，自动过期）。
  • **数据库**：建立唯一索引字段（如`request_id`），插入时去重。
• **示例代码（Redis）**：
  ```java
  public boolean handleRequest(String requestId, RequestData data) {
      // 尝试存储请求ID（原子操作）
      Boolean isNew = redisTemplate.opsForValue().setIfAbsent(requestId, "processed", 1, TimeUnit.HOURS);
      if (isNew != null && isNew) {
          // 执行业务逻辑
          processPayment(data);
          return true;
      } else {
          // 返回已处理结果
          return false;
      }
  }
  ```

**方案二：数据库唯一约束**
• **适用场景**：写操作（如订单创建）。
• **实现方式**：
  • 在数据库表中为唯一业务字段（如订单号）添加唯一索引。
  • 插入数据时，若重复则捕获唯一性异常，返回已有结果。
• **示例SQL**：
  ```sql
  CREATE TABLE orders (
      order_id VARCHAR(64) PRIMARY KEY,
      user_id INT,
      amount DECIMAL,
      UNIQUE KEY uniq_order_id (order_id)
  );
  ```

**方案三：乐观锁（版本号控制）**
• **流程**：
  1. **读取数据**：获取当前数据及其版本号。
  2. **更新校验**：提交更新时，验证版本号是否匹配。
  3. **版本更新**：若匹配则更新数据并递增版本号。
• **示例代码**：
  ```java
  public boolean deductInventory(String productId, int quantity, int version) {
      // 更新库存，校验版本号
      String sql = "UPDATE inventory SET stock = stock - ?, version = version + 1 
                    WHERE product_id = ? AND version = ?";
      int rows = jdbcTemplate.update(sql, quantity, productId, version);
      return rows > 0;
  }
  ```

**方案四：状态机（业务状态流转）**
• **实现方式**：
  • 定义业务状态（如订单状态：待支付、已支付、已取消）。
  • 仅允许在特定状态下执行操作，拒绝非法状态变更。
• **示例流程**：
  ```plaintext
  订单支付：
  待支付 →（支付成功）→ 已支付
  重复支付请求 →（当前状态已为“已支付”）→ 直接返回成功
  ```

**方案五：分布式锁**
• **适用场景**：需要强一致性的短时操作。
• **实现步骤**：
  1. **获取锁**：使用分布式锁（如Redis RedLock）锁定资源。
  2. **处理请求**：执行业务逻辑。
  3. **释放锁**：操作完成后释放锁。
• **注意事项**：设置合理的锁超时时间，避免死锁。

#### 3. **组合方案设计**
**场景：支付系统幂等性**
1. **唯一ID生成**：
   • 客户端生成支付流水号（如 `PAY-20231101-0001`）。
2. **Redis校验**：
   • 使用 `SETNX` 检查流水号是否已存在。
3. **数据库兜底**：
   • 支付记录表添加唯一索引，防止Redis失效时数据库拦截。
4. **状态机控制**：
   • 支付状态从“未支付”到“已支付”，拒绝重复状态变更。
5. **异常处理**：
   • 网络超时重试时，客户端携带同一流水号，服务端返回原结果。

#### 4. **关键注意事项**
• **原子性操作**：ID的存储与检查必须原子化（如Redis的SETNX或数据库事务）。
• **高可用存储**：确保ID存储系统（Redis/DB）的可靠性和性能。
• **过期策略**：设置合理的ID过期时间（如1小时），避免存储膨胀。
• **客户端协作**：前端防重（如按钮禁用）与后端幂等性结合，减少无效请求。
• **日志与监控**：
  • 记录所有请求的ID、状态和处理结果。
  • 监控ID冲突率、存储系统负载等指标。

#### 5. **异常场景处理**
• **重复请求**：服务端直接返回已处理结果。
• **处理中状态**：若操作耗时较长，返回中间状态（如“处理中”），客户端轮询结果。
• **存储系统故障**：降级策略（如本地缓存ID），但需权衡一致性与可用性。

#### 6. **测试策略**
• **单元测试**：验证单服务幂等性逻辑。
• **集成测试**：模拟分布式环境下重复请求、网络分区等场景。
• **压力测试**：高并发下校验存储系统的性能（如Redis QPS）。

### 总结
分布式幂等性设计需结合业务场景选择方案，核心是**唯一请求标识**与**原子性校验**，辅以状态控制、乐观锁等机制。通过多层次防护（客户端+服务端+存储）确保操作唯一性，最终实现系统的高可靠与数据一致性。
