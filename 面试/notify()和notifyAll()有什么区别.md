在 Java 多线程编程中，`notify()` 和 `notifyAll()` 都是用于唤醒等待线程的方法，但它们的核心区别在于 **唤醒的线程数量** 和 **适用场景**。以下是详细对比：

---

### **1. 核心区别**
| **方法**       | **行为**                                                                 | **适用场景**                                                                 |
|----------------|-------------------------------------------------------------------------|----------------------------------------------------------------------------|
| `notify()`     | 随机唤醒 **一个** 正在等待该对象锁的线程（唤醒的线程由 JVM 选择）。           | 所有等待线程的唤醒条件相同，且只需一个线程处理任务（如单生产者-单消费者模型）。             |
| `notifyAll()`  | 唤醒 **所有** 正在等待该对象锁的线程，这些线程会竞争锁，最终只有一个线程获得锁。 | 等待线程的唤醒条件可能不同，或需要确保所有线程都有机会重新检查条件（如多条件等待或资源池管理）。 |

---

### **2. 关键细节**
#### **(1) `notify()` 的潜在风险**
假设有多个线程因不同条件等待（如生产者等待队列空、消费者等待队列满）：
```java
synchronized (lock) {
    while (条件不满足) {
        lock.wait();
    }
    // 处理任务...
}
```
- **问题**：如果使用 `notify()`，可能唤醒一个不满足当前条件的线程（如生产者被唤醒但队列已满），导致该线程再次进入等待，而真正需要被唤醒的线程（如消费者）未被选中。
- **结果**：可能发生 **线程饥饿**（某些线程永远无法被唤醒）。

#### **(2) `notifyAll()` 的安全性**
- 通过唤醒所有线程，确保每个线程都有机会重新检查自己的条件。
- 虽然竞争锁会增加开销，但能避免因条件误判导致的死锁或饥饿。

---

### **3. 代码示例对比**
#### **场景：生产者-消费者模型**
假设队列容量为 1，有 2 个生产者和 2 个消费者。

##### **使用 `notify()` 的问题**
```java
// 生产者代码
synchronized (queue) {
    while (queue.isFull()) {
        queue.wait();
    }
    queue.add(item);
    queue.notify(); // 可能唤醒另一个生产者，而非消费者
}

// 消费者代码
synchronized (queue) {
    while (queue.isEmpty()) {
        queue.wait();
    }
    queue.remove();
    queue.notify(); // 可能唤醒另一个消费者，而非生产者
}
```
- **风险**：生产者唤醒生产者，消费者唤醒消费者，导致线程无限等待。（也算死锁）

##### **使用 `notifyAll()` 的改进**
```java
synchronized (queue) {
    while (queue.isFull()) {
        queue.wait();
    }
    queue.add(item);
    queue.notifyAll(); // 唤醒所有线程（生产者和消费者）
}

synchronized (queue) {
    while (queue.isEmpty()) {
        queue.wait();
    }
    queue.remove();
    queue.notifyAll(); // 唤醒所有线程（生产者和消费者）
}
```
- **结果**：所有线程重新竞争锁并检查条件，避免饥饿。

---

### **4. 性能权衡**
| **方法**       | **性能**                               | **安全性**                               |
|----------------|---------------------------------------|-----------------------------------------|
| `notify()`     | 高效（仅唤醒一个线程，减少竞争和上下文切换）   | 低（可能因条件误判导致线程饥饿）              |
| `notifyAll()`  | 低效（唤醒所有线程，增加竞争和上下文切换）     | 高（确保所有线程有机会检查条件）               |

---

### **5. 最佳实践**
1. **优先使用 `notifyAll()`**  
   除非能确保所有等待线程的唤醒条件相同，否则使用 `notifyAll()` 更安全。
   
2. **始终在循环中检查条件**  
   使用 `while` 而非 `if` 判断条件，防止虚假唤醒（Spurious Wakeup）：
   ```java
   synchronized (lock) {
       while (条件不满足) { // 不要用 if！
           lock.wait();
       }
       // 处理任务...
   }
   ```

3. **明确区分等待条件**  
   如果不同线程等待不同条件，使用多个条件对象（`Condition` 类）而非单一锁，结合 `signal()`（类似 `notify()`）定向唤醒。

---

### **6. 总结**
| **选择策略**                | **`notify()`**                          | **`notifyAll()`**                        |
|----------------------------|-----------------------------------------|------------------------------------------|
| **线程唤醒数量**             | 1 个                                    | 所有                                      |
| **适用场景**                | 单一条件，所有等待线程处理相同任务          | 多条件，或需确保所有线程重新检查条件           |
| **代码安全性**              | 需严格保证条件一致性                      | 更安全，避免饥饿                           |
| **性能**                   | 更高                                    | 更低（但正确性优先）                        |

**最终建议**：在不确定时，优先使用 `notifyAll()`，除非对性能有极端要求且能确保逻辑安全。
