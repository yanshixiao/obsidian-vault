Java中常见的线程池主要通过`Executors`工厂类创建，每种线程池适用于不同的并发场景。以下是主要类型及其核心特性：

---

### 1. **FixedThreadPool（固定大小线程池）**
- **创建方式**：  
  `Executors.newFixedThreadPool(int nThreads)`
- **核心参数**：  
  - 核心线程数 = 最大线程数 = `nThreads`  
  - 使用**无界队列**（`LinkedBlockingQueue`）
- **特点**：  
  - 线程数固定，即使空闲也不会回收  
  - 任务队列无界，可能堆积大量任务导致OOM
- **适用场景**：  
  适合**长期稳定**的并发负载（如服务器处理请求）

```java
ExecutorService fixedPool = Executors.newFixedThreadPool(4);
```

---

### 2. **CachedThreadPool（缓存线程池）**
- **创建方式**：  
  `Executors.newCachedThreadPool()`
- **核心参数**：  
  - 核心线程数 = 0  
  - 最大线程数 = `Integer.MAX_VALUE`  
  - 空闲线程存活时间 = 60秒  
  - 使用**同步队列**（`SynchronousQueue`）
- **特点**：  
  - 线程数量可无限扩展，空闲线程自动回收  
  - 高并发时可能创建过多线程导致资源耗尽
- **适用场景**：  
  短时、高频的**异步小任务**（如HTTP请求）

```java
ExecutorService cachedPool = Executors.newCachedThreadPool();
```

---

### 3. **SingleThreadExecutor（单线程池）**
- **创建方式**：  
  `Executors.newSingleThreadExecutor()`
- **核心参数**：  
  - 核心线程数 = 最大线程数 = 1  
  - 使用**无界队列**（`LinkedBlockingQueue`）
- **特点**：  
  - 保证任务按提交顺序**串行执行**  
  - 无界队列同样有OOM风险
- **适用场景**：  
  需要**顺序执行任务**且避免资源竞争的场景（如日志写入）

```java
ExecutorService singlePool = Executors.newSingleThreadExecutor();
```

---

### 4. **ScheduledThreadPool（定时任务线程池）**
- **创建方式**：  
  `Executors.newScheduledThreadPool(int corePoolSize)`
- **核心参数**：  
  - 支持定时或周期性任务调度  
  - 使用**延迟队列**（`DelayedWorkQueue`）
- **特点**：  
  - 可执行固定频率或固定延迟的任务  
  - 核心线程数固定，非核心线程可回收
- **适用场景**：  
  定时任务（如数据定时同步）、周期性任务（如监控心跳）

```java
ScheduledExecutorService scheduledPool = Executors.newScheduledThreadPool(2);
// 延迟1秒后执行，每隔3秒重复执行
scheduledPool.scheduleAtFixedRate(task, 1, 3, TimeUnit.SECONDS);
```

---

### 5. **WorkStealingPool（工作窃取线程池，Java 8+）**
- **创建方式**：  
  `Executors.newWorkStealingPool(int parallelism)`
- **核心参数**：  
  - 基于`ForkJoinPool`实现  
  - 默认并行度 = CPU核心数
- **特点**：  
  - 使用**工作窃取算法**提升吞吐量  
  - 适合处理**分治型任务**（子任务可拆分）
- **适用场景**：  
  计算密集型任务（如递归分解、并行流处理）

```java
ExecutorService workStealingPool = Executors.newWorkStealingPool();
```

---

### 6. **自定义线程池（推荐方式）**
直接使用`ThreadPoolExecutor`构造函数创建，避免`Executors`的潜在风险：
```java
ThreadPoolExecutor customPool = new ThreadPoolExecutor(
    corePoolSize,    // 核心线程数
    maxPoolSize,     // 最大线程数
    keepAliveTime,   // 空闲线程存活时间
    TimeUnit.MILLISECONDS,
    new ArrayBlockingQueue<>(queueCapacity), // 有界队列
    new ThreadPoolExecutor.AbortPolicy()     // 拒绝策略
);
```

---

### 线程池对比总结
| 线程池类型          | 核心线程数      | 最大线程数      | 任务队列          | 适用场景                   |
|---------------------|-----------------|-----------------|-------------------|--------------------------|
| FixedThreadPool     | 固定            | 固定            | 无界队列          | 长期稳定的并发任务         |
| CachedThreadPool    | 0               | Integer.MAX_VALUE | 同步队列          | 短时高频的异步任务         |
| SingleThreadExecutor| 1               | 1               | 无界队列          | 顺序执行任务               |
| ScheduledThreadPool | 自定义          | Integer.MAX_VALUE | 延迟队列          | 定时或周期性任务           |
| WorkStealingPool    | CPU核心数       | CPU核心数       | 工作窃取队列      | 分治型计算密集型任务       |

---

### 注意事项
1. **避免使用无界队列**  
   `FixedThreadPool`和`SingleThreadExecutor`默认使用无界队列（`LinkedBlockingQueue`），任务堆积可能导致内存溢出（OOM）。
   
2. **谨慎选择拒绝策略**  
   - `AbortPolicy`（默认）：抛出`RejectedExecutionException`  
   - `CallerRunsPolicy`：由提交任务的线程执行任务  
   - `DiscardPolicy`：静默丢弃任务  
   - `DiscardOldestPolicy`：丢弃队列中最旧的任务

3. **监控线程池状态**  
   通过`ThreadPoolExecutor`提供的方法（如`getActiveCount()`、`getQueue().size()`）实时监控线程池负载。

---

### 最佳实践
- **优先使用自定义线程池**：通过`ThreadPoolExecutor`显式设置核心参数，避免资源耗尽风险。
- **合理设置队列容量**：使用有界队列（如`ArrayBlockingQueue`）并配合合适的拒绝策略。
- **明确任务类型**：IO密集型任务可设置较多线程数（如2*CPU核心数），CPU密集型任务则与CPU核心数相当。

通过合理选择线程池类型及参数配置，可以显著提升系统在高并发场景下的性能和稳定性。
