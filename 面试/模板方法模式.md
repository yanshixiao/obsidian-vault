模板方法模式（**Template Method Pattern**）是一种行为型设计模式，**定义一个操作中的算法骨架，将某些步骤延迟到子类中实现**，从而在不改变算法结构的前提下，允许子类重写特定步骤的具体实现。

---

### **核心思想**
• **算法骨架固定**：父类定义算法的流程（如步骤1→步骤2→步骤3）。
• **步骤可变**：子类可重写某些步骤的实现，但不改变整体流程。

---

### **模式结构**
1. **抽象类（Abstract Class）**  
   • 定义模板方法（`final`修饰，防止子类修改流程）。  
   • 包含具体方法（已实现的步骤）和抽象方法（需子类实现的步骤）。  

2. **具体子类（Concrete Class）**  
   • 实现抽象类中定义的抽象方法，覆盖某些具体方法（可选）。  

---

### **Java 实现示例：咖啡与茶的制作流程**
#### **1. 抽象类：饮料制作流程**
```java
public abstract class Beverage {
    // 模板方法（final防止子类覆盖流程）
    public final void prepareRecipe() {
        boilWater();
        brew();
        pourInCup();
        addCondiments();
    }

    // 具体方法（通用步骤）
    private void boilWater() {
        System.out.println("Boiling water");
    }

    private void pourInCup() {
        System.out.println("Pouring into cup");
    }

    // 抽象方法（需子类实现）
    protected abstract void brew();
    protected abstract void addCondiments();
}
```

#### **2. 具体子类：咖啡**
```java
public class Coffee extends Beverage {
    @Override
    protected void brew() {
        System.out.println("Brewing coffee grounds");
    }

    @Override
    protected void addCondiments() {
        System.out.println("Adding sugar and milk");
    }
}
```

#### **3. 具体子类：茶**
```java
public class Tea extends Beverage {
    @Override
    protected void brew() {
        System.out.println("Steeping the tea");
    }

    @Override
    protected void addCondiments() {
        System.out.println("Adding lemon");
    }
}
```

#### **4. 客户端调用**
```java
public class Client {
    public static void main(String[] args) {
        Beverage coffee = new Coffee();
        coffee.prepareRecipe();
        // 输出：
        // Boiling water
        // Brewing coffee grounds
        // Pouring into cup
        // Adding sugar and milk

        Beverage tea = new Tea();
        tea.prepareRecipe();
        // 输出：
        // Boiling water
        // Steeping the tea
        // Pouring into cup
        // Adding lemon
    }
}
```

### **适用场景**
1. **框架设计**：定义标准流程，允许用户自定义部分步骤。  
   • 示例：Spring的 `JdbcTemplate`（`execute()` 方法封装了连接、执行、关闭资源，用户只需实现 `PreparedStatement` 逻辑）。  

2. **复用算法骨架**：多个子类有共享的算法流程，但细节不同。  
   • 示例：不同支付方式（支付宝、微信）的支付流程（验证→执行→通知）。  

3. **控制流程扩展点**：允许子类重写特定步骤，但禁止修改流程顺序。  

---

### **优缺点分析**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **代码复用**：抽取公共流程到父类，减少冗余代码。 | 1. **步骤数量限制**：算法流程的步骤数量不宜过多，否则维护困难。 |
| 2. **扩展可控**：子类仅扩展特定步骤，不破坏整体流程。 | 2. **继承强耦合**：子类必须继承抽象类，无法通过组合实现。       |
| 3. **符合开闭原则**：新增子类不影响已有代码。       |                                   |

---

### **模板方法模式 vs 策略模式**
| **维度**       | **模板方法模式**                  | **策略模式**                          |
|----------------|----------------------------------|--------------------------------------|
| **实现方式**    | 继承：子类覆盖父类方法。            | 组合：通过接口委托策略对象实现算法。          |
| **关注点**      | 算法流程固定，步骤可变。            | 算法整体可替换，灵活性更高。               |
| **适用场景**    | 流程固定，仅部分步骤需定制。         | 需要动态切换完整算法（如排序、加密策略）。     |

---

### **总结**
模板方法模式通过**定义算法骨架**和**延迟步骤实现**，实现了代码复用与扩展的平衡。其核心价值在于：  
• **流程标准化**：确保所有子类遵循相同的算法流程。  
• **灵活扩展**：子类可自由定制特定步骤，适应不同需求。  

在框架设计、业务流程控制等场景中，模板方法模式是提升代码复用性和维护性的有效工具。
