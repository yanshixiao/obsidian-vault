线程池的核心线程数（Core Pool Size）是线程池长期保持存活的最小线程数量，即使这些线程处于空闲状态。它的设置直接影响系统的资源利用率、吞吐量和响应速度。以下是设置核心线程数的核心原则和具体方法：

---

**一、核心线程数的作用**
1. 减少线程创建开销：核心线程会常驻内存，避免频繁创建/销毁线程的开销。
2. 应对突发流量：当任务量突增时，核心线程可以快速处理请求，避免队列堆积。
3. 资源占用控制：核心线程数过多会导致内存/CPU资源浪费，过少则可能成为性能瓶颈。

---

**二、设置核心线程数的核心原则**
**1. 根据任务类型选择策略**
• CPU密集型任务（如计算、加密、压缩）：  

  核心线程数 ≈ CPU逻辑核心数 + 1  
  原因：避免线程切换开销，留一个线程应对突发任务。  
  示例：  
  ```java
  int corePoolSize = Runtime.getRuntime().availableProcessors() + 1;
  ```

• IO密集型任务（如网络请求、数据库操作）：  

  核心线程数 ≈ CPU逻辑核心数 * 2  
  原因：线程在等待IO时会阻塞，多线程可充分利用CPU空闲时间。  
  示例：  
  ```java
  int corePoolSize = Runtime.getRuntime().availableProcessors() * 2;
  ```

• 混合型任务：  

  根据任务比例调整，或通过压测找到最优值。

**2. 结合系统资源限制**
• 内存限制：每个线程需要约 `1MB` 的栈内存（默认值，可调整）。  

  公式：  
  ```java
  核心线程数 ≤ (可用内存 - 其他内存占用) / 单线程内存占用
  ```
• CPU限制：避免过多线程导致CPU频繁切换（上下文切换开销）。


**3. 队列类型的影响**
• 有界队列（如 `ArrayBlockingQueue`）：  

  核心线程数需足够处理大部分任务，避免队列满触发拒绝策略。
• 无界队列（如 `LinkedBlockingQueue`）：  

  核心线程数可适当减少，因为队列能缓冲突发流量。

---

**三、经典场景示例**
**1. Web服务器（HTTP请求处理）**
• 任务类型：IO密集型（网络I/O、数据库查询）。  

• 建议核心线程数：  

  ```java
  int corePoolSize = Runtime.getRuntime().availableProcessors() * 2;
  ```

**2. 批处理任务（数据计算）**
• 任务类型：CPU密集型（数学计算、图像处理）。  

• 建议核心线程数：  

  ```java
  int corePoolSize = Runtime.getRuntime().availableProcessors() + 1;
  ```

**3. 消息队列消费者**
• 任务类型：IO密集型（拉取消息、反序列化）。  

• 建议核心线程数：  

  ```java
  int corePoolSize = Runtime.getRuntime().availableProcessors() * 2 ~ 4;
  ```

---

**四、动态调整核心线程数**
部分线程池（如 `ThreadPoolExecutor`）支持动态修改核心线程数，适用于负载波动较大的场景：
```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(...);
executor.setCorePoolSize(newCorePoolSize); // 动态调整
```

**动态调整的条件**
1. 系统负载变化：通过监控CPU/内存使用率动态扩缩容。  
2. 业务高峰/低谷：例如电商秒杀场景，高峰期扩容，低谷期缩容。

---

**五、避坑指南**
1. 避免过度依赖默认值：  
   `Executors.newFixedThreadPool()` 默认核心线程数等于 `Integer.MAX_VALUE`，可能导致OOM。
2. 拒绝策略的配合：  
   核心线程数 + 队列容量不足时，需合理配置拒绝策略（如丢弃任务、记录日志）。
3. 监控与调优：  
   • 监控指标：线程池活跃线程数、队列堆积量、任务完成时间。  

   • 工具：Prometheus + Grafana、Spring Boot Actuator、Arthas。


---

**六、总结：设置步骤**
1. 确定任务类型：CPU密集型 or IO密集型。  
2. 计算初始值：  
   • CPU密集型：`CPU核心数 + 1`  

   • IO密集型：`CPU核心数 * 2`  

3. 结合资源限制：内存、CPU、队列容量。  
4. 压测验证：通过工具（JMeter、Gatling）模拟流量，观察系统表现。  
5. 动态调整：根据监控数据持续优化。

---

**示例代码**
```java
int cpuCount = Runtime.getRuntime().availableProcessors();
int corePoolSize = cpuCount * 2; // IO密集型任务
int maxPoolSize = cpuCount * 4;
long keepAliveTime = 60L;
TimeUnit unit = TimeUnit.SECONDS;
BlockingQueue<Runnable> workQueue = new LinkedBlockingQueue<>(1000);

ThreadPoolExecutor executor = new ThreadPoolExecutor(
    corePoolSize,
    maxPoolSize,
    keepAliveTime,
    unit,
    workQueue,
    new ThreadPoolExecutor.CallerRunsPolicy()
);
```

通过合理设置核心线程数，可以在资源利用率和系统稳定性之间找到最佳平衡点。
