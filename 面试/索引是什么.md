### 索引是什么？

**索引是数据库中用于加速数据查询的一种数据结构**，类似于书籍的目录。它通过建立特定字段的快速查找路径，帮助数据库系统跳过全表扫描，直接定位目标数据，从而显著提高查询效率。

---

### **索引的核心作用**
1. **加速查询**：避免全表扫描，快速定位数据（尤其是`WHERE`、`JOIN`、`ORDER BY`等操作）。
2. **优化排序和分组**：对`ORDER BY`和`GROUP BY`字段建立索引可减少排序时间。
3. **强制唯一性**：唯一索引（如主键）确保数据不重复。

---

### **索引的常见结构**
数据库索引的实现依赖于高效的数据结构，最常见的两种是：

#### 1. **B+树索引（默认结构）**
- **特点**：
  - 所有数据存储在叶子节点，内部节点仅存键值和指针。
  - 叶子节点通过指针形成有序链表，支持高效的范围查询（如`BETWEEN`、`>`、`<`）。
- **适用场景**：适合范围查询和排序（如按时间查询订单）。

**图形示例**：
```
         [内部节点]
        /  10  |  20  \  
       /        |        \
[叶子节点1] -> [叶子节点2] -> [叶子节点3]
(5,10)       (15,20)       (25,30)
```

#### 2. **哈希索引**
- **特点**：
  - 通过哈希函数将键值映射到固定位置，查询速度接近`O(1)`。
  - **仅支持等值查询**（如`=`、`IN`），不支持范围查询。
- **适用场景**：内存数据库（如Redis）、等值查询频繁的场景。

---

### **索引的代价**
1. **存储占用**：索引需要额外的磁盘空间（例如B+树的节点）。
2. **写操作变慢**：每次插入、删除或更新数据时，索引需要同步维护。
3. **设计复杂度**：不合理的索引可能导致性能下降（如过多索引或低效字段选择）。

---

### **何时使用索引？**
| **场景**                | **推荐操作**                     |
|-------------------------|---------------------------------|
| 高频查询字段（如用户ID）  | 创建单列索引                    |
| 多条件查询（如城市+年龄） | 创建复合索引（注意字段顺序）     |
| 唯一约束（如手机号）      | 创建唯一索引                    |
| 全文搜索（如文章内容）    | 使用全文索引（如Elasticsearch） |

---

### **SQL示例**
```sql
-- 创建单列索引
CREATE INDEX idx_user_email ON users (email);

-- 创建复合索引（优先按城市筛选，再按年龄排序）
CREATE INDEX idx_city_age ON employees (city, age);

-- 删除索引
DROP INDEX idx_city_age;
```

---

### **总结**
- **索引的本质是“用空间换时间”**，通过预存数据的查找结构来加速查询。
- **B+树**是数据库默认的索引结构，平衡了查询效率和维护成本。
- **合理设计索引**（如选择高频字段、避免冗余）是数据库优化的关键。
