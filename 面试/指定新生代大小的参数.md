在 JVM 中指定新生代（Young Generation）的大小，可通过以下参数实现：

---

### **1. 固定新生代大小（推荐）**
**参数**：`-Xmn<size>`  
**示例**：  
```bash
-Xmn2g        # 新生代固定为 2GB
-Xmn512m      # 新生代固定为 512MB
```
**特点**：  
- 直接指定新生代的**固定大小**（包含 Eden + Survivor 区），老年代大小 = 堆总大小（`-Xmx`） - 新生代大小。  
- 适合明确新生代需求的场景（如对象分配速率高、短期存活对象多）。  

---

### **2. 按比例分配新生代大小**
**参数**：`-XX:NewRatio=<ratio>`  
**示例**：  
```bash
-XX:NewRatio=3  # 老年代:新生代 = 3:1（新生代占堆的 1/4）
```
**特点**：  
- 通过**老年代与新生代的比例**动态分配内存（总堆大小由 `-Xmx` 决定）。  
- 适合堆总大小固定但需动态调整的场景。  

---

### **3. 手动设置初始和最大新生代大小**
**参数**：  
```bash
-XX:NewSize=<size>      # 新生代初始大小
-XX:MaxNewSize=<size>   # 新生代最大大小
```
**示例**：  
```bash
-XX:NewSize=1g -XX:MaxNewSize=2g  # 新生代初始 1GB，最大 2GB
```
**特点**：  
- 允许新生代在指定范围内动态调整（需与 `-Xmx` 配合使用）。  
- 适用于内存需求波动较大的应用。  

---

### **4. 调整 Survivor 区比例**
**参数**：`-XX:SurvivorRatio=<ratio>`  
**示例**：  
```bash
-XX:SurvivorRatio=8  # Eden:Survivor = 8:1（每个 Survivor 占新生代的 1/10）
```
**特点**：  
- 控制 **Eden 区与单个 Survivor 区的比例**，影响对象晋升策略。  
- 默认值为 `8`（HotSpot JVM）。  

---

### **5. 不同垃圾回收器的注意事项**
| **垃圾回收器**       | **新生代设置建议**                                                                 |
|----------------------|-----------------------------------------------------------------------------------|
| **G1**               | 无需手动设置新生代大小（由 G1 自动管理 Region 分配）。                            |
| **Parallel Scavenge**| 优先使用 `-Xmn` 固定大小，或 `-XX:NewRatio` 按比例分配。                          |
| **CMS**              | 建议明确设置 `-Xmn`，避免老年代碎片问题。                                         |

---

### **调优建议**
1. **监控先行**：使用 `jstat -gc <pid>` 或 GC 日志分析新生代 GC 频率和对象晋升情况。  
2. **避免过大/过小**：  
   - 过小 → 频繁 Minor GC，增加 STW 时间。  
   - 过大 → 老年代空间不足，触发 Full GC。  
3. **经验值参考**：  
   - 新生代通常占堆总大小的 **25%~50%**（如堆 8G，新生代 2G~4G）。  
   - Survivor 区建议占总新生代的 **10%~20%**（通过 `-XX:SurvivorRatio` 调整）。  

---

### **验证参数生效**
使用 `jinfo -flags <pid>` 查看 JVM 实际生效参数，确认新生代配置是否正确应用。
