### **一、`if` 与 `while` 的条件检查机制**

#### **1. `if` 只检查一次的原因**
当线程调用 `wait()` 后，会释放锁并进入等待状态。被唤醒（通过 `notify()`/`notifyAll()` 或虚假唤醒）后，线程需重新获取锁才能继续执行。**关键区别在于被唤醒后的行为**：

| **代码结构**       | **被唤醒后的行为**                                                                 |
|-------------------|----------------------------------------------------------------------------------|
| **`if` 判断**      | 线程被唤醒后，直接执行 `wait()` 后的代码，不再检查条件。                             |
| **`while` 循环**   | 线程被唤醒后，重新进入循环条件检查，只有条件满足时才会执行后续代码，否则再次 `wait()`。 |

#### **2. 示例对比**
假设队列容量为 1，初始为空，有两个消费者线程（C1 和 C2）：

##### **(1) 使用 `if` 的错误场景**
```java
synchronized (lock) {
    if (queue.isEmpty()) { // 错误：用 if 判断
        lock.wait();
    }
    queue.poll(); // 消费数据
}
```
- **流程**：
  1. **生产者 P** 插入数据，队列满，调用 `notifyAll()`。
  2. **C1 和 C2** 被唤醒，竞争锁。
  3. **C1** 获取锁，消费数据，队列变空。
  4. **C2** 获取锁，由于 `if` 不再检查条件，直接执行 `queue.poll()`，但队列已空，抛出异常（如 `NoSuchElementException`）。

##### **(2) 使用 `while` 的正确场景**
```java
synchronized (lock) {
    while (queue.isEmpty()) { // 正确：用 while 检查
        lock.wait();
    }
    queue.poll(); // 消费数据
}
```
- **流程**：
  1. **生产者 P** 插入数据，队列满，调用 `notifyAll()`。
  2. **C1 和 C2** 被唤醒，竞争锁。
  3. **C1** 获取锁，消费数据，队列变空。
  4. **C2** 获取锁，重新检查 `while (queue.isEmpty())`，发现队列为空，再次进入 `wait()`，避免异常。

#### **3. 核心区别总结**
| **场景**               | **`if` 判断**                                | **`while` 循环**                          |
|-----------------------|---------------------------------------------|------------------------------------------|
| **虚假唤醒**           | 直接执行后续代码，导致状态不一致                | 重新检查条件，避免无效操作                  |
| **多线程竞争**         | 多个线程可能同时操作不满足条件的资源            | 确保每次操作前条件有效                     |
| **代码安全性**         | 低（易引发异常）                              | 高（防御性编程）                           |


---

### **二、总结**
| **问题**             | **核心原因**                                          | **解决方案**                       |
| ------------------ | ------------------------------------------------- | ------------------------------ |
| `if` 与 `while` 的区别 | `if` 只检查一次条件，无法防御虚假唤醒和多线程竞争；`while` 在每次唤醒后重新检查条件。 | 始终用 `while` 循环检查条件。            |


**关键结论**：
1. **`while` 是防御性编程的必备手段**，确保条件真正满足后再操作资源。
2. **`notifyAll()` 避免唤醒策略不当**，确保所有线程有机会重新检查状态。
