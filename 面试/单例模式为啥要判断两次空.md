单例模式中双重检查锁定（Double-Checked Locking）的两次 `if (instance == null)` 检查，是为了在多线程环境下 **兼顾性能与线程安全**。以下是详细的解释：

---

### **一、单例模式的常见实现问题**
#### **1. 基础懒汉式单例（线程不安全）**
```java
public class Singleton {
    private static Singleton instance;
    
    private Singleton() {}
    
    public static Singleton getInstance() {
        if (instance == null) {              // 第一次检查
            instance = new Singleton();      // 非线程安全！
        }
        return instance;
    }
}
```
- **问题**：多线程环境下，多个线程可能同时通过第一次检查，导致多次实例化。

#### **2. 加锁的懒汉式单例（性能差）**
```java
public class Singleton {
    private static Singleton instance;
    
    private Singleton() {}
    
    public static synchronized Singleton getInstance() { // 同步整个方法
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```
- **问题**：每次调用 `getInstance()` 都需要加锁，性能开销大。

---

### **二、双重检查锁定（Double-Checked Locking）**
#### **1. 代码实现**
```java
public class Singleton {
    private static volatile Singleton instance; // 必须用 volatile
    
    private Singleton() {}
    
    public static Singleton getInstance() {
        if (instance == null) {                  // 第一次检查：避免不必要的同步
            synchronized (Singleton.class) {     // 同步代码块
                if (instance == null) {          // 第二次检查：防止重复实例化
                    instance = new Singleton();  // 创建实例
                }
            }
        }
        return instance;
    }
}
```

#### **2. 两次检查的作用**
| **检查阶段**     | **目的**                                                                 |
|-----------------|-------------------------------------------------------------------------|
| **第一次检查**   | 避免每次调用 `getInstance()` 都进入同步代码块，提升性能。                  |
| **第二次检查**   | 确保在同步代码块内，只有一个线程能创建实例，防止多线程竞争下的重复实例化。       |

---

### **三、为什么需要两次检查？**
#### **1. 第一次检查的作用**
- **性能优化**：  
  如果实例已存在，直接返回，无需进入同步代码块，减少锁竞争的开销。

#### **2. 第二次检查的作用**
- **线程安全**：  
  当多个线程同时通过第一次检查时，只有一个线程能进入同步块。  
  假设线程 A 正在创建实例，线程 B 在同步块外等待。  
  线程 A 释放锁后，线程 B 进入同步块，若没有第二次检查，线程 B 会重复创建实例。

---

### **四、为什么必须加 `volatile`？**
#### **1. 指令重排序问题**
对象的实例化操作 `instance = new Singleton()` 可能被 JVM 拆分为以下步骤：
```java
memory = allocate();    // 1. 分配内存空间
ctorInstance(memory);   // 2. 初始化对象
instance = memory;      // 3. 将引用指向内存地址
```
- **问题**：JVM 可能重排序为 `1 → 3 → 2`。此时其他线程可能拿到未初始化的对象（`instance != null`，但对象未构造完成）。

#### **2. `volatile` 的作用**
- **禁止指令重排序**：  
  确保对象的初始化操作（步骤 2）在引用赋值（步骤 3）之前完成。
- **保证可见性**：  
  线程对 `volatile` 变量的修改对其他线程立即可见。

---

### **五、不满足双重检查锁定的后果**
#### **1. 没有第二次检查**
```java
public static Singleton getInstance() {
    if (instance == null) {                  // 第一次检查
        synchronized (Singleton.class) {
            instance = new Singleton();      // 可能重复实例化
        }
    }
    return instance;
}
```
- **问题**：多个线程通过第一次检查后，依次进入同步块，重复创建实例。

#### **2. 没有 `volatile`**
```java
private static Singleton instance; // 不加 volatile
```
- **问题**：其他线程可能拿到未初始化的对象，导致程序行为异常（如空指针）。

---

### **六、总结**
| **设计要点**         | **作用**                                                                 |
|---------------------|-------------------------------------------------------------------------|
| **第一次 `if` 检查**  | 提升性能，避免不必要的锁竞争。                                             |
| **同步代码块**       | 确保同一时间只有一个线程进入实例化逻辑。                                     |
| **第二次 `if` 检查**  | 防止进入同步块的线程重复实例化。                                             |
| **`volatile` 关键字** | 禁止指令重排序，保证对象初始化的可见性和有序性。                               |

**双重检查锁定是性能与线程安全的完美平衡**，但需严格遵循实现规范（尤其是 `volatile` 的使用）。
