装饰器模式（**Decorator Pattern**）是一种结构型设计模式，**动态地给对象添加额外职责**，且不改变其原有结构。它通过组合替代继承，实现功能的灵活扩展，符合 **开闭原则**（对扩展开放，对修改关闭）。

---

### **核心思想**
• **包装对象**：创建一个装饰器类，包裹原始对象并增强其功能。
• **透明扩展**：装饰器与原始对象实现同一接口，客户端无需感知是否被装饰。

---

### **模式结构**
1. **组件接口（Component）**：定义对象的核心功能。
2. **具体组件（Concrete Component）**：实现组件接口的原始对象。
3. **装饰器基类（Decorator）**：继承组件接口，持有组件对象的引用。
4. **具体装饰器（Concrete Decorator）**：扩展装饰器基类，添加新功能。

---

### **Java 实现示例：咖啡订单系统**
#### **1. 组件接口：咖啡**
```java
public interface Coffee {
    String getDescription();
    double cost();
}
```

#### **2. 具体组件：基础咖啡**
```java
public class SimpleCoffee implements Coffee {
    @Override
    public String getDescription() {
        return "Simple Coffee";
    }

    @Override
    public double cost() {
        return 2.0;
    }
}
```

#### **3. 装饰器基类：咖啡装饰器**
```java
public abstract class CoffeeDecorator implements Coffee {
    protected Coffee decoratedCoffee;

    public CoffeeDecorator(Coffee coffee) {
        this.decoratedCoffee = coffee;
    }

    @Override
    public String getDescription() {
        return decoratedCoffee.getDescription();
    }

    @Override
    public double cost() {
        return decoratedCoffee.cost();
    }
}
```

#### **4. 具体装饰器：牛奶和糖**
```java
// 牛奶装饰器
public class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee coffee) {
        super(coffee);
    }

    @Override
    public String getDescription() {
        return super.getDescription() + ", Milk";
    }

    @Override
    public double cost() {
        return super.cost() + 0.5;
    }
}

// 糖装饰器
public class SugarDecorator extends CoffeeDecorator {
    public SugarDecorator(Coffee coffee) {
        super(coffee);
    }

    @Override
    public String getDescription() {
        return super.getDescription() + ", Sugar";
    }

    @Override
    public double cost() {
        return super.cost() + 0.2;
    }
}
```

#### **5. 客户端调用**
```java
public class Client {
    public static void main(String[] args) {
        // 基础咖啡
        Coffee coffee = new SimpleCoffee();
        System.out.println(coffee.getDescription() + " : $" + coffee.cost());

        // 加牛奶
        coffee = new MilkDecorator(coffee);
        System.out.println(coffee.getDescription() + " : $" + coffee.cost());

        // 加糖
        coffee = new SugarDecorator(coffee);
        System.out.println(coffee.getDescription() + " : $" + coffee.cost());
    }
}

// 输出：
// Simple Coffee : $2.0
// Simple Coffee, Milk : $2.5
// Simple Coffee, Milk, Sugar : $2.7
```

### **应用场景**
1. **动态扩展功能**：如Java I/O流（`BufferedInputStream` 装饰 `FileInputStream`）。
2. **避免子类膨胀**：当通过继承会导致大量子类时（如GUI控件样式叠加）。
3. **运行时添加职责**：如Web中间件（日志、权限校验等功能的动态组合）。

---

### **优缺点对比**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **灵活扩展**：动态添加或移除功能。       | 1. **类数量增加**：每个功能需单独装饰器类。 |
| 2. **开闭原则**：不修改原有代码即可扩展。    | 2. **复杂度提升**：多层装饰可能影响可读性。 |
| 3. **替代继承**：通过组合实现功能复用。      |                                   |

---

### **装饰器模式 vs 继承**
| **维度**       | **装饰器模式**                  | **继承**                    |
|----------------|-------------------------------|----------------------------|
| **扩展方式**    | 动态组合，运行时添加功能。          | 静态编译时扩展，需预定义子类。    |
| **灵活性**      | 可任意组合多层装饰。               | 功能扩展受限于继承层次。          |
| **耦合度**      | 低耦合，依赖接口而非具体实现。       | 高耦合，子类依赖父类实现。         |

---

### **实际应用案例**
1. **Java I/O流**：  
   ```java
   InputStream in = new FileInputStream("data.txt");
   in = new BufferedInputStream(in); // 装饰为缓冲流
   in = new DataInputStream(in);     // 装饰为数据流
   ```
2. **Spring Web 拦截器**：通过装饰器链处理HTTP请求。
3. **GUI框架**：如为按钮动态添加边框、阴影等样式。

---

### **总结**
装饰器模式通过**组合对象**和**透明扩展**，解决了继承带来的类膨胀问题，适用于需要动态、灵活扩展功能的场景。其核心在于将功能拆分为独立的装饰器类，按需叠加使用，是构建可维护、可扩展系统的有效工具。
