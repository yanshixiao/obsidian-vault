### 适配器模式详解

**适配器模式（Adapter Pattern）** 是一种结构型设计模式，用于**将一个类的接口转换为另一个客户端期望的接口**，从而解决接口不兼容的问题。它通过包装现有类的方法，使得原本无法一起工作的类可以协同工作。

---

#### **核心概念**
1. **目标接口（Target）**：客户端期望的接口。
2. **被适配者（Adaptee）**：需要被适配的已有类（接口不兼容）。
3. **适配器（Adapter）**：实现目标接口，并包装被适配者的实例，将客户端的调用转换为对被适配者的调用。

---

#### **两种实现方式**
| **类型**       | **实现方式**                      | **适用场景**                     |
|----------------|----------------------------------|--------------------------------|
| **类适配器**    | 通过继承被适配类，实现目标接口（需多继承）。 | 适用于适配者和目标接口差异较小的情况。 |
| **对象适配器**  | 通过组合被适配类的实例，实现目标接口。     | 更灵活，Java等单继承语言常用。       |

---

#### **对象适配器示例（Java）**
**场景**：旧打印机接口 `OldPrinter` 需要适配到新接口 `NewPrinter`。

1. **目标接口（新打印机）**：
   ```java
   public interface NewPrinter {
       void print(String document);
   }
   ```

2. **被适配者（旧打印机）**：
   ```java
   public class OldPrinter {
       public void printDocument(String doc) {
           System.out.println("Printing: " + doc);
       }
   }
   ```

3. **适配器类**：
   ```java
   public class PrinterAdapter implements NewPrinter {
       private OldPrinter oldPrinter; // 组合被适配对象
   
       public PrinterAdapter(OldPrinter oldPrinter) {
           this.oldPrinter = oldPrinter;
       }
   
       @Override
       public void print(String document) {
           oldPrinter.printDocument(document); // 调用旧接口的方法
       }
   }
   ```

4. **客户端调用**：
   ```java
   public class Client {
       public static void main(String[] args) {
           OldPrinter oldPrinter = new OldPrinter();
           NewPrinter adapter = new PrinterAdapter(oldPrinter);
           adapter.print("Sample Document"); // 输出: Printing: Sample Document
       }
   }
   ```

---

#### **类适配器示例（Java，需多继承，实际通过接口实现）**
由于Java不支持多继承，可通过实现目标接口并继承被适配类：
```java
public class ClassAdapter extends OldPrinter implements NewPrinter {
    @Override
    public void print(String document) {
        printDocument(document); // 直接调用父类方法
    }
}
```

---

#### **适配器模式 vs 其他模式**
| **模式**       | **区别**                          |
|----------------|----------------------------------|
| **装饰器模式**  | 增强对象功能，接口保持一致。             |
| **代理模式**    | 控制对象访问，接口不变。                 |
| **外观模式**    | 简化复杂系统的接口，可能涉及多个子系统的适配。 |

---

#### **应用场景**
1. **整合第三方库**：当第三方库的接口与当前系统不兼容时。
2. **新旧系统兼容**：旧代码需要与新系统协同工作。
3. **接口标准化**：统一多个不同接口为通用接口（如日志框架适配）。

---

#### **优缺点**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **复用旧代码**：无需修改现有类即可复用。 | 1. **过度使用增加复杂度**：需谨慎设计避免类爆炸。 |
| 2. **灵活解耦**：客户端与具体实现解耦。    | 2. **性能开销**：适配器转发可能带来轻微延迟。   |

---

#### **总结**
适配器模式通过**接口转换**，解决类之间因接口不兼容导致的协作问题。其核心在于：
• **对象适配器**：优先使用组合，灵活且适用于单继承语言。
• **类适配器**：需多继承支持，灵活性较低。

在系统升级、多平台兼容或整合第三方库时，适配器模式是平滑过渡的桥梁，有效提升代码复用性和系统扩展性。
