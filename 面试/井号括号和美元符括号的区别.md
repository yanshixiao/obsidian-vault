在 MyBatis 中，`#{}` 和 `${}` 是两种不同的参数占位符，**核心区别在于 SQL 注入防护和预编译机制**。以下是具体对比：

---

### **1. `#{}`：预编译占位符**
- **工作机制**  
  - 将参数替换为 `?`，通过 `PreparedStatement` 预编译，参数值由数据库驱动处理。
  - 自动处理类型转换（如字符串添加单引号）。
- **核心优势**  
  - **防止 SQL 注入**：参数值与 SQL 语句分离，避免恶意拼接。
  - **性能优化**：预编译的 SQL 可被数据库缓存，提高重复执行效率。
- **使用场景**  
  - 传递 **数据值**（如 `WHERE id = #{id}`）。
  - 动态 SQL 中的条件参数（如 `<if test="name != null">AND name = #{name}</if>`）。

**示例**：
```xml
<select id="getUser" resultType="User">
  SELECT * FROM users WHERE id = #{userId}
</select>
```
实际执行的 SQL：
```sql
SELECT * FROM users WHERE id = ?  -- 参数值由数据库安全处理
```

---

### **2. `${}`：字符串替换**
- **工作机制**  
  - 直接替换为参数的原始值，生成完整的 SQL 语句。
  - 不处理类型（如字符串需手动加引号）。
- **风险与问题**  
  - **SQL 注入风险**：若参数值来源不可控（如用户输入），可能被恶意拼接。
  - **无预编译优化**：每次生成新 SQL，影响执行效率。
- **使用场景**  
  - 动态指定 **SQL 片段**（如表名、列名、排序字段等）。
  - 需要直接拼接 SQL 的场景（如动态分页 `LIMIT ${offset}, ${limit}`）。

**示例**：
```xml
<select id="getUsersByTable" resultType="User">
  SELECT * FROM ${tableName} WHERE role = #{role}
</select>
```
实际执行的 SQL：
```sql
SELECT * FROM admin_users WHERE role = ?  -- 表名直接替换，role 参数安全处理
```

---

### **对比总结**
| **特性**         | **`#{}`**                          | **`${}`**                          |
|------------------|------------------------------------|------------------------------------|
| **安全性**       | 防 SQL 注入                        | 存在 SQL 注入风险                  |
| **预编译**       | 支持，参数与 SQL 分离              | 不支持，直接拼接 SQL               |
| **类型处理**     | 自动添加引号、类型转换             | 原样替换，需手动处理类型           |
| **性能**         | 高（可缓存预编译语句）             | 低（每次生成新 SQL）               |
| **适用场景**     | 传递数据值（如 `WHERE` 条件）      | 动态 SQL 片段（如表名、排序字段）  |

---

### **最佳实践**
1. **优先使用 `#{}`**：确保安全性和性能，尤其在处理用户输入时。
2. **谨慎使用 `${}`**：仅在必须动态拼接 SQL 结构时使用，且需严格过滤参数（如校验表名合法性）。
3. **示例场景**：
   - **安全用法**：`ORDER BY ${sortColumn} DESC`（确保 `sortColumn` 值白名单校验）。
   - **错误用法**：`WHERE username = '${name}'`（应改为 `#{name}` 避免注入）。
