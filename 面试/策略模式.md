策略模式（**Strategy Pattern**）是一种行为型设计模式，**定义一系列算法，将它们封装成独立的策略类**，并在运行时动态切换这些算法。通过将算法与使用它的客户端解耦，策略模式使系统更灵活、可扩展，并符合 **开闭原则**（对扩展开放，对修改关闭）。

---

### **核心思想**
• **算法独立**：每个算法封装为一个策略类，实现统一接口。
• **动态切换**：客户端可根据需要选择或切换策略，无需修改原有代码。
• **解耦**：客户端依赖抽象策略接口，而非具体实现。

---

### **模式结构**
| **角色**          | **说明**                          |
|------------------|-----------------------------------|
| **策略接口（Strategy）** | 定义算法的公共接口（如 `execute()`）。 |
| **具体策略类（Concrete Strategy）** | 实现策略接口，封装具体算法。 |
| **上下文类（Context）** | 持有策略对象，负责调用策略方法。可动态切换策略。 |

---

### **Java 实现示例：支付方式选择**
#### **1. 策略接口（支付策略）**
```java
public interface PaymentStrategy {
    void pay(double amount);
}
```

#### **2. 具体策略类（不同支付方式）**
```java
// 支付宝支付
public class AlipayStrategy implements PaymentStrategy {
    @Override
    public void pay(double amount) {
        System.out.println("Paid " + amount + " via Alipay");
    }
}

// 微信支付
public class WechatPayStrategy implements PaymentStrategy {
    @Override
    public void pay(double amount) {
        System.out.println("Paid " + amount + " via WeChat Pay");
    }
}

// 信用卡支付
public class CreditCardStrategy implements PaymentStrategy {
    @Override
    public void pay(double amount) {
        System.out.println("Paid " + amount + " via Credit Card");
    }
}
```

#### **3. 上下文类（支付上下文）**
```java
public class PaymentContext {
    private PaymentStrategy strategy;

    public PaymentContext(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    // 动态切换策略
    public void setStrategy(PaymentStrategy strategy) {
        this.strategy = strategy;
    }

    // 执行支付
    public void executePayment(double amount) {
        strategy.pay(amount);
    }
}
```

#### **4. 客户端调用**
```java
public class Client {
    public static void main(String[] args) {
        PaymentContext context = new PaymentContext(new AlipayStrategy());
        context.executePayment(100.0); // 使用支付宝支付

        context.setStrategy(new CreditCardStrategy());
        context.executePayment(200.0); // 切换为信用卡支付
    }
}
```

---

### **适用场景**
1. **多算法切换**：如排序算法（快速排序、归并排序）、支付方式、数据压缩策略。
2. **消除条件分支**：替代复杂的 `if-else` 或 `switch-case` 逻辑。
3. **框架扩展点**：允许用户自定义插件化算法（如Spring的 `ResourceLoader`）。

---

### **优缺点分析**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **开闭原则**：新增策略无需修改客户端代码。 | 1. **类数量增加**：每个策略需单独类。 |
| 2. **解耦**：算法与客户端逻辑分离。         | 2. **客户端需知悉策略差异**：需了解不同策略的适用场景。 |
| 3. **动态切换**：运行时灵活选择算法。        |                                   |

---

### **策略模式 vs 工厂模式**
| **维度**       | **策略模式**                      | **工厂模式**                    |
|----------------|----------------------------------|---------------------------------|
| **核心目的**    | 封装算法，实现动态切换。            | 封装对象创建过程，解耦实例化逻辑。    |
| **关注点**      | 行为（如何执行）。                 | 创建（如何生成对象）。               |
| **使用阶段**    | 运行时动态选择行为。               | 编译时或运行时决定创建哪种对象。      |

---

### **实际应用案例**
1. **Java Comparator**：通过实现 `Comparator` 接口定义不同的排序策略。
   ```java
   List<Integer> numbers = Arrays.asList(3, 1, 4, 1, 5);
   Collections.sort(numbers, Comparator.reverseOrder()); // 降序策略
   ```
2. **Spring ResourceLoader**：根据资源路径前缀（`classpath:`、`file:`）选择加载策略。
3. **支付网关**：支持多种支付方式（支付宝、微信、PayPal）的无缝切换。

---

### **总结**
策略模式通过 **封装算法族** 和 **动态委派行为**，将算法的选择权交给客户端，提升系统的灵活性和可维护性。其核心价值在于：
• **消除条件分支**：用多态替代复杂的条件判断。
• **简化扩展**：新增策略只需添加新类，无需修改现有代码。

在需要频繁切换或扩展算法的场景中（如电商促销策略、游戏技能系统），策略模式是优化代码结构的利器。
