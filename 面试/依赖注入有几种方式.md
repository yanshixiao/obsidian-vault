在 Spring 框架中，依赖注入（Dependency Injection, DI）是实现控制反转（IoC）的核心技术，主要通过以下 **3 种方式** 实现，每种方式有各自的适用场景和优缺点：

---

### **一、构造函数注入（Constructor Injection）**
#### **特点**
• 通过类的构造函数注入依赖。
• **推荐用于强制依赖**（必须存在的依赖）。
• **支持不可变（`final`）字段**，确保依赖在对象创建后不可修改。

#### **示例代码**
```java
@Service
public class UserService {
    private final UserRepository userRepo;

    // 构造函数注入
    @Autowired
    public UserService(UserRepository userRepo) {
        this.userRepo = userRepo;
    }
}
```

#### **优点**
1. **不可变性**：依赖可声明为 `final`，避免运行时修改。
2. **明确性**：构造函数参数直接反映类的必要依赖。
3. **易于测试**：通过构造函数传递 Mock 对象，无需反射或框架支持。

#### **适用场景**
• 核心依赖（如数据库访问组件、配置类）。
• 需要保证依赖不可变的场景（如多线程安全）。

---

### **二、Setter 方法注入（Setter Injection）**
#### **特点**
• 通过 Setter 方法注入依赖。
• **适用于可选依赖**（非必须的依赖）。
• 依赖在对象创建后仍可修改。

#### **示例代码**
```java
@Service
public class UserService {
    private UserRepository userRepo;

    // Setter 方法注入
    @Autowired
    public void setUserRepository(UserRepository userRepo) {
        this.userRepo = userRepo;
    }
}
```

#### **优点**
1. **灵活性**：允许动态更新依赖（如热部署场景）。
2. **可选性**：可通过 `@Autowired(required = false)` 标记非必须依赖。

#### **适用场景**
• 可选依赖（如日志组件、缓存管理器）。
• 需要运行时动态替换依赖的场景。

---

### **三、字段注入（Field Injection）**
#### **特点**
• 直接通过字段注入依赖（无需构造函数或 Setter 方法）。
• **代码简洁但隐藏依赖关系**，不推荐作为首选方式。

#### **示例代码**
```java
@Service
public class UserService {
    @Autowired  // 字段注入
    private UserRepository userRepo;
}
```

#### **优点**
1. **代码简洁**：减少模板代码（如构造函数或 Setter 方法）。
2. **快速开发**：适合简单场景或原型验证。

#### **缺点**
1. **破坏封装性**：依赖通过反射直接注入，绕过正常构造流程。
2. **不可变性缺失**：依赖无法声明为 `final`。
3. **测试困难**：需依赖 Spring 容器或反射工具注入 Mock 对象。

#### **适用场景**
• 快速开发或小型项目。
• 非核心依赖的临时性使用。

---

### **四、接口注入（Interface Injection）**
#### **特点**
• 依赖通过接口定义的方法注入（需实现特定接口）。
• **Spring 中已弃用**，仅在某些旧框架（如 EJB）中使用。

#### **示例代码**
```java
public interface UserRepositoryInjector {
    void injectUserRepository(UserRepository userRepo);
}

@Service
public class UserService implements UserRepositoryInjector {
    private UserRepository userRepo;

    @Override
    public void injectUserRepository(UserRepository userRepo) {
        this.userRepo = userRepo;
    }
}
```

#### **缺点**
• **侵入性强**：需强制实现接口。
• **灵活性差**：依赖与接口绑定，难以扩展。

---

### **五、依赖注入方式对比**
| **方式**          | 不可变性 | 明确性 | 可测试性 | 适用场景               | 推荐程度 |
|-------------------|----------|--------|----------|------------------------|----------|
| **构造函数注入** | ✅        | ✅      | ✅        | 核心依赖、强制依赖     | ⭐⭐⭐⭐⭐  |
| **Setter 注入**   | ❌        | ❌      | ✅        | 可选依赖、动态依赖     | ⭐⭐⭐⭐   |
| **字段注入**      | ❌        | ❌      | ❌        | 快速开发、非关键依赖   | ⭐⭐      |
| **接口注入**      | ❌        | ❌      | ❌        | 旧框架兼容（不推荐）   | ❌        |

---

### **六、最佳实践建议**
1. **优先使用构造函数注入**：保证依赖不可变，提升代码健壮性。
2. **慎用字段注入**：仅在工具类、配置类等简单场景中使用。
3. **避免接口注入**：与现代框架设计理念冲突。

#### **Spring 官方推荐**
• **构造函数注入** 是 Spring 团队的首选方式，尤其与 Lombok 的 `@RequiredArgsConstructor` 结合时，代码更简洁：
  ```java
  @Service
  @RequiredArgsConstructor
  public class UserService {
      private final UserRepository userRepo;
  }
  ```

---

### **总结**
依赖注入的三种主要方式是 **构造函数注入**、**Setter 注入** 和 **字段注入**，其中构造函数注入是 Spring 推荐的最佳实践。选择合适的方式，可以显著提升代码的可维护性、可测试性和扩展性。
