享元模式（**Flyweight Pattern**）是一种结构型设计模式，**通过共享相似对象来减少内存占用**，适用于存在大量重复对象且对象状态可分时（如游戏中的树木、文本编辑器中的字符）。其核心是分离 **内部状态（可共享）** 和 **外部状态（不可共享）**，通过复用内部状态优化资源使用。

---

### **核心思想**
• **内部状态（Intrinsic State）**：对象中不变且可共享的部分（如字符的字体、颜色）。
• **外部状态（Extrinsic State）**：对象中可变且需客户端传入的部分（如字符的位置、大小）。
• **享元工厂（Flyweight Factory）**：管理共享对象池，确保相同内部状态的对象只创建一次。

---

### **模式结构**
| **角色**          | **说明**                          |
|------------------|-----------------------------------|
| **Flyweight**     | 定义享元对象的接口，包含外部状态的操作方法。 |
| **ConcreteFlyweight** | 实现Flyweight接口，存储内部状态。       |
| **FlyweightFactory** | 管理享元对象池，提供获取共享对象的方法。  |
| **Client**         | 维护外部状态，通过工厂获取享元对象。      |

---

### **Java 实现示例：共享颜色圆**
#### **1. 定义享元接口**
```java
public interface Shape {
    void draw(int x, int y); // 外部状态（坐标）由客户端传入
}
```

#### **2. 具体享元类（内部状态：颜色）**
```java
public class Circle implements Shape {
    private String color; // 内部状态（可共享）
    
    public Circle(String color) {
        this.color = color;
    }

    @Override
    public void draw(int x, int y) { // 外部状态（坐标）
        System.out.println("Draw a " + color + " circle at (" + x + "," + y + ")");
    }
}
```

#### **3. 享元工厂**
```java
import java.util.HashMap;
import java.util.Map;

public class ShapeFactory {
    private static final Map<String, Shape> circleMap = new HashMap<>();

    public static Shape getCircle(String color) {
        // 存在则直接返回，不存在则创建并缓存
        return circleMap.computeIfAbsent(color, key -> new Circle(color));
    }
}
```

#### **4. 客户端调用**
```java
public class Client {
    public static void main(String[] args) {
        String[] colors = {"Red", "Green", "Blue"};
        for (int i = 0; i < 10; i++) {
            // 随机获取颜色（共享内部状态）
            String color = colors[(int) (Math.random() * colors.length)];
            Shape circle = ShapeFactory.getCircle(color);
            circle.draw(i * 10, i * 20); // 传入外部状态（坐标）
        }
    }
}
```

### **应用场景**
1. **图形渲染**：游戏中的大量树木、粒子效果（共享纹理、模型，仅位置不同）。  
2. **文本处理**：文档中的重复字符（共享字体、颜色，位置和大小由外部维护）。  
3. **线程池/数据库连接池**：复用已创建的资源，减少开销。  

---

### **优缺点分析**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **内存优化**：减少重复对象的创建，节省内存。 | 1. **增加复杂性**：需区分内部/外部状态。 |
| 2. **性能提升**：减少GC频率和对象初始化时间。 | 2. **线程安全问题**：共享对象需考虑并发访问。 |
| 3. **资源复用**：适合高频使用的轻量级对象。   |                                   |

---

### **享元模式 vs 单例模式**
| **维度**       | **享元模式**                      | **单例模式**                    |
|----------------|-----------------------------------|---------------------------------|
| **对象数量**    | 多个对象（按内部状态分类共享）         | 单个对象（全局唯一实例）           |
| **核心目的**    | 优化资源使用，减少重复对象            | 控制实例数量，确保全局访问点        |
| **状态管理**    | 分离内部/外部状态，客户端维护外部状态   | 无状态或状态内部管理               |

---

### **总结**
享元模式通过 **共享内部状态** 和 **外部化可变状态**，有效解决了大量相似对象导致的内存消耗问题。其关键在于：
• **识别可共享的内部状态**（如颜色、字体）。  
• **合理管理享元对象池**（工厂模式实现）。  
• **确保线程安全**（如使用 `ConcurrentHashMap`）。  

在游戏开发、文本处理等需要处理海量轻量级对象的场景中，享元模式是优化性能的利器。
