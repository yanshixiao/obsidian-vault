Elasticsearch 的核心概念可以用以下层级关系表示：**集群（Cluster）→ 节点（Node）→ 索引（Index）→ 文档（Document）**，而 **类型（Type）** 在 7.x 版本后已废弃。以下是详细解释：

---

### **1. 集群（Cluster）**
• **定义**：由多个节点（Node）组成的分布式系统，共同存储和检索数据。  
• **核心作用**：  
  • 实现高可用性（通过副本分片）。  
  • 支持横向扩展（通过增加节点）。  
• **示例**：  
  • 生产环境通常有一个集群，包含多个节点。  
  • 集群名称是唯一标识（默认名为 `elasticsearch`）。

---

### **2. 节点（Node）**
• **定义**：集群中的一个独立服务器，存储数据并参与搜索和索引操作。  
• **核心作用**：  
  • 存储分片（Shard）的数据。  
  • 处理查询请求。  
• **节点类型**：  
  • **主节点（Master Node）**：负责集群管理（如索引创建、分片分配）。  
  • **数据节点（Data Node）**：存储数据并执行数据操作。  
  • **协调节点（Coordinating Node）**：路由请求并聚合结果（默认所有节点都是协调节点）。  
  • **Ingest 节点**：预处理文档（如解析日志）。  

**示例**：  
```yaml
# 配置文件设置节点角色（elasticsearch.yml）
node.master: true   # 可作为主节点
node.data: false    # 不作为数据节点
```

---

### **3. 索引（Index）**
• **定义**：具有相似特征的文档集合（类似关系型数据库中的 **表**）。  
• **核心作用**：  
  • 定义字段的映射（Mapping，即数据结构）。  
  • 管理分片（Shard）和副本（Replica）。  
• **关键特性**：  
  • 索引名称必须唯一（如 `products`、`logs-2023`）。  
  • 每个索引可划分为多个分片（Shard）以实现分布式存储。  

**示例**：  
```json
PUT /products
{
  "settings": { "number_of_shards": 3 },  // 主分片数
  "mappings": {                           // 字段定义
    "properties": {
      "title": { "type": "text" }, 
      "price": { "type": "float" }
    }
  }
}
```

---

### **4. 文档（Document）**
• **定义**：索引中的基本数据单元（类似关系型数据库中的 **行**），以 JSON 格式存储。  
• **核心作用**：  
  • 存储实际数据（如一条商品信息）。  
  • 每个文档有唯一 ID（`_id`），可自动生成或手动指定。  

**示例**：  
```json
PUT /products/_doc/1
{
  "title": "智能手机", 
  "price": 2999.0, 
  "category": "电子产品"
}
```

---

### **5. 类型（Type）**（已废弃）
• **历史背景**：7.x 版本前，索引中可定义多个类型（类似数据库中的表），用于逻辑分区。  
• **废弃原因**：  
  • 导致数据建模混乱（不同类型字段冲突）。  
  • 性能问题（同一索引中不同类型的数据存储效率低）。  
• **现状**：  
  • 7.x 版本后**不再支持**，8.x 版本完全移除。  
  • 所有文档统一存储在 `_doc` 类型下。  

---

### **总结**
• **集群**：多节点组成的分布式系统。  
• **节点**：集群中的单个服务器，承担不同角色。  
• **索引**：文档的集合，定义数据结构和分片策略。  
• **文档**：实际存储的 JSON 数据单元。  
• **类型**：已废弃，不再使用。  

**层级关系**：  
```
集群（Cluster）  
  ├─ 节点（Node）  
  │    ├─ 索引（Index）  
  │    │    ├─ 文档（Document）  
  │    │    └─ 分片（Shard）  
  │    └─ 分片副本（Replica）  
  └─ 协调节点（Coordinating Node）
```
