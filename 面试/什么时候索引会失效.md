MySQL索引失效的常见情况及示例：

---

### **1. 违反最左前缀原则（联合索引）**
• **场景**：联合索引未从最左列开始查询，或中间跳过字段。
• **示例**：
  ```sql
  -- 联合索引为 (a, b, c)
  SELECT * FROM table WHERE b = 1;               -- 未使用a，索引失效
  SELECT * FROM table WHERE a = 1 AND c = 2;      -- 跳过b，c无法利用索引
  ```

---

### **2. 对索引列进行运算或函数操作**
• **场景**：对索引列使用函数、表达式或类型转换。
• **示例**：
  ```sql
  SELECT * FROM table WHERE YEAR(create_time) = 2023;  -- 对列使用函数
  SELECT * FROM table WHERE price * 2 = 100;           -- 对列进行运算
  SELECT * FROM table WHERE CAST(id AS CHAR) = '123';  -- 隐式类型转换
  ```

---

### **3. 使用通配符开头的 `LIKE` 查询**
• **场景**：`LIKE` 以 `%` 或 `_` 开头时无法利用索引。
• **示例**：
  ```sql
  SELECT * FROM table WHERE name LIKE '%abc';   -- 全表扫描
  SELECT * FROM table WHERE name LIKE '_abc';   -- 全表扫描
  ```

---

### **4. 使用 `OR` 连接非索引列**
• **场景**：`OR` 连接的条件中至少有一个列无索引。
• **示例**：
  ```sql
  -- 假设列a有索引，列b无索引
  SELECT * FROM table WHERE a = 1 OR b = 2;     -- 全表扫描
  ```

---

### **5. 隐式类型转换**
• **场景**：索引列与查询值类型不匹配（如字符串与数字比较）。
• **示例**：
  ```sql
  -- 假设 name 是 VARCHAR 类型
  SELECT * FROM table WHERE name = 123;         -- 隐式转换为字符串，索引失效
  ```

---

### **6. 使用 `!=` 或 `<>` 运算符**
• **场景**：非等值查询可能导致全表扫描。
• **示例**：
  ```sql
  SELECT * FROM table WHERE status != 'active'; -- 可能全表扫描
  ```

---

### **7. 数据量过小或覆盖大部分数据**
• **场景**：优化器认为全表扫描比索引更快。
• **示例**：
  ```sql
  -- 表仅100行数据，即使有索引也可能全表扫描
  SELECT * FROM table WHERE id > 1; 
  ```

---

### **8. `ORDER BY` 与索引顺序冲突**
• **场景**：排序字段顺序或方向与索引不一致。
• **示例**：
  ```sql
  -- 索引为 (a, b)
  SELECT * FROM table ORDER BY b, a;    -- 顺序不一致，可能无法利用索引排序
  SELECT * FROM table ORDER BY a DESC, b ASC; -- 混合排序方向，索引失效
  ```

---

### **9. 使用 `IN` 或 `NOT IN`**
• **场景**：`IN` 列表过长或 `NOT IN` 导致全表扫描。
• **示例**：
  ```sql
  SELECT * FROM table WHERE id NOT IN (1, 2, 3);   -- 可能全表扫描
  ```



---

### **10. 统计信息不准确**
• **场景**：表的统计信息未更新，导致优化器误判。
• **解决**：定期执行 `ANALYZE TABLE table_name;`。

---

### **其他注意事项**
• **覆盖索引**：即使 `WHERE` 未用索引，若查询字段全在索引中，仍可能触发索引扫描。
• **索引合并**：多个单列索引可能被合并，但效率通常低于联合索引。

---

### **总结**
索引失效的根本原因是 **MySQL无法高效利用索引的有序性**。建议通过 `EXPLAIN` 分析查询计划，并结合实际数据分布优化索引设计。
