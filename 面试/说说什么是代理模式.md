代理模式（**Proxy Pattern**）是一种结构型设计模式，**通过代理对象控制对原始对象的访问**，从而在不修改原始对象代码的前提下，**增强或扩展其功能**。代理模式常用于权限控制、延迟加载、日志记录、远程调用等场景。

---

### **核心思想**
• **职责分离**：代理对象与原始对象实现同一接口，客户端通过代理间接访问原始对象。
• **功能增强**：代理对象可在调用原始对象前后插入额外逻辑（如权限校验、日志记录）。

---

### **代理模式的三种类型**
| **类型**       | **说明**                          | **典型应用**                  |
|----------------|-----------------------------------|-----------------------------|
| **静态代理**    | 手动编写代理类，代理特定接口。           | 简单业务场景，代理逻辑固定。         |
| **动态代理**    | 运行时动态生成代理类，无需手动编写。       | AOP（如Spring事务管理）、远程调用。 |
| **虚拟代理**    | 延迟创建开销大的对象，直到真正需要时才实例化。 | 图片懒加载、大文件预加载。          |

### **静态代理示例（Java）**
```java
// 1. 定义接口
interface Image {
    void display();
}

// 2. 原始对象类
class RealImage implements Image {
    private String filename;

    public RealImage(String filename) {
        this.filename = filename;
        loadFromDisk(); // 初始化时加载图片（假设耗时）
    }

    private void loadFromDisk() {
        System.out.println("Loading image: " + filename);
    }

    @Override
    public void display() {
        System.out.println("Displaying image: " + filename);
    }
}

// 3. 代理类
class ProxyImage implements Image {
    private RealImage realImage;
    private String filename;

    public ProxyImage(String filename) {
        this.filename = filename;
    }

    @Override
    public void display() {
        if (realImage == null) {
            realImage = new RealImage(filename); // 延迟加载
        }
        realImage.display();
    }
}

// 4. 客户端调用
public class Client {
    public static void main(String[] args) {
        Image image = new ProxyImage("test.jpg");
        image.display(); // 第一次调用时加载并显示
        image.display(); // 直接显示，无需重复加载
    }
}
```

### **动态代理示例（Java，基于JDK动态代理）**
```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

// 1. 接口
interface UserService {
    void saveUser();
}

// 2. 原始对象类
class UserServiceImpl implements UserService {
    @Override
    public void saveUser() {
        System.out.println("Saving user...");
    }
}

// 3. 动态代理处理器
class LogHandler implements InvocationHandler {
    private Object target; // 被代理的原始对象

    public LogHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        System.out.println("Before method: " + method.getName());
        Object result = method.invoke(target, args); // 调用原始方法
        System.out.println("After method: " + method.getName());
        return result;
    }
}

// 4. 客户端调用
public class Client {
    public static void main(String[] args) {
        UserService realService = new UserServiceImpl();
        UserService proxy = (UserService) Proxy.newProxyInstance(
            realService.getClass().getClassLoader(),
            realService.getClass().getInterfaces(),
            new LogHandler(realService)
        );
        proxy.saveUser(); // 输出日志并执行业务
    }
}
```

### **代理模式的应用场景**
1. **远程代理（Remote Proxy）**：  
   • 用于访问远程对象（如RPC调用），隐藏网络通信细节。
   • 示例：Java RMI、Dubbo框架的远程服务代理。

2. **虚拟代理（Virtual Proxy）**：  
   • 延迟创建开销大的对象，直到真正需要时才初始化。
   • 示例：网页图片懒加载、大型文档的逐页加载。

3. **保护代理（Protection Proxy）**：  
   • 控制对敏感对象的访问权限。
   • 示例：Spring Security中的方法级权限控制。

4. **日志与监控代理（Logging/Monitoring Proxy）**：  
   • 记录方法调用日志或监控性能。
   • 示例：Spring AOP的切面编程。

5. **缓存代理（Cache Proxy）**：  
   • 缓存请求结果，避免重复计算或查询。
   • 示例：MyBatis的二级缓存机制。

### **代理模式的优缺点**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **职责清晰**：代理类专注于增强逻辑，原始类专注业务。 | 1. **增加系统复杂度**：需额外维护代理类。 |
| 2. **开闭原则**：无需修改原始对象即可扩展功能。      | 2. **性能损耗**：动态代理反射调用略慢。   |
| 3. **灵活控制**：可动态决定是否使用原始对象。        |                                   |

---

### **代理模式 vs 装饰器模式**
| **维度**       | **代理模式**                      | **装饰器模式**                  |
|----------------|-----------------------------------|---------------------------------|
| **目的**        | 控制访问，增强非功能性逻辑（如权限、日志）。 | 增强对象的功能（如添加新行为）。          |
| **关系**        | 代理类和原始类关系固定，通常一一对应。     | 装饰器可嵌套叠加，动态添加多个功能。       |
| **初始化时机**  | 代理对象通常在客户端代码中显式创建。      | 装饰器通过组合方式在运行时动态构造。       |

---

### **总结**
代理模式通过**间接访问对象**和**插入增强逻辑**，实现了对原始对象的控制与扩展。其核心价值在于：
• **解耦**：将非业务逻辑（如日志、权限）从原始对象中剥离。
• **灵活扩展**：动态代理技术（如JDK Proxy、CGLIB）大幅提升了开发效率。

在Spring框架、RPC调用、AOP编程等场景中，代理模式是支撑其核心功能的重要基础。
