在Java中，线程间的通信主要通过**共享内存**或**消息传递**实现。以下是常见的线程通信机制及其详细说明：

---

### 一、基于共享内存的通信
通过共享变量和同步机制实现，需要解决**线程安全**和**可见性**问题。

#### 1. **synchronized + wait/notify**
- **原理**：通过对象的监视器锁（Monitor）协调线程。
- **示例**（生产者-消费者模型）：
  ```java
  public class SharedBuffer {
      private final Queue<Integer> queue = new LinkedList<>();
      private final int maxSize = 5;
      private final Object lock = new Object();

      // 生产者方法
      public void produce(int value) throws InterruptedException {
          synchronized(lock) {
              while(queue.size() == maxSize) {
                  lock.wait(); // 队列满时等待
              }
              queue.add(value);
              lock.notifyAll(); // 唤醒消费者
          }
      }

      // 消费者方法
      public int consume() throws InterruptedException {
          synchronized(lock) {
              while(queue.isEmpty()) {
                  lock.wait(); // 队列空时等待
              }
              int value = queue.poll();
              lock.notifyAll(); // 唤醒生产者
              return value;
          }
      }
  }
  ```
- **特点**：
  - 必须配合`synchronized`使用。
  - `wait()`会释放锁，`notify()`只唤醒一个等待线程，`notifyAll()`唤醒所有。

#### 2. **volatile变量**
- **原理**：通过内存屏障保证变量的**可见性**（不保证原子性）。
- **示例**（标志位控制）：
  ```java
  public class FlagExample {
      private volatile boolean flag = false;

      public void setFlag() {
          flag = true; // 对其他线程立即可见
      }

      public void waitForFlag() {
          while(!flag) {
              // 空循环等待（可结合Thread.yield()减少CPU占用）
          }
      }
  }
  ```
- **适用场景**：简单状态标志位，无需原子操作。

### 二、基于消息传递的通信
通过队列或工具类传递数据，解耦线程间的直接依赖。

#### 1. **BlockingQueue**
- **原理**：线程安全的阻塞队列，支持生产者和消费者模型。
- **示例**：
  ```java
  public class BlockingQueueDemo {
      private final BlockingQueue<String> queue = new ArrayBlockingQueue<>(10);

      // 生产者线程
      Runnable producer = () -> {
          try {
              queue.put("Message");
          } catch (InterruptedException e) {
              Thread.currentThread().interrupt();
          }
      };

      // 消费者线程
      Runnable consumer = () -> {
          try {
              String msg = queue.take();
              System.out.println("Received: " + msg);
          } catch (InterruptedException e) {
              Thread.currentThread().interrupt();
          }
      };
  }
  ```
- **优点**：无需手动处理同步，支持容量控制。

#### 2. **PipedInputStream/PipedOutputStream**
- **原理**：通过管道流传递字节数据。
- **示例**：
  ```java
  public class PipeExample {
      public static void main(String[] args) throws IOException {
          PipedInputStream pis = new PipedInputStream();
          PipedOutputStream pos = new PipedOutputStream();
          pis.connect(pos); // 连接管道

          // 生产者线程写数据
          new Thread(() -> {
              try {
                  pos.write("Hello from pipe!".getBytes());
                  pos.close();
              } catch (IOException e) { /* 处理异常 */ }
          }).start();

          // 消费者线程读数据
          new Thread(() -> {
              try {
                  int data;
                  while((data = pis.read()) != -1) {
                      System.out.print((char) data);
                  }
                  pis.close();
              } catch (IOException e) { /* 处理异常 */ }
          }).start();
      }
  }
  ```
- **缺点**：实际开发中较少使用，更推荐`BlockingQueue`。

### 三、高级同步工具
Java并发包（`java.util.concurrent`）提供的线程协调工具。

#### 1. **CountDownLatch**
- **原理**：等待指定数量的线程完成任务。
- **示例**：
  ```java
  public class CountDownLatchDemo {
      public static void main(String[] args) throws InterruptedException {
          CountDownLatch latch = new CountDownLatch(3);

          for(int i=0; i<3; i++) {
              new Thread(() -> {
                  // 执行任务
                  latch.countDown();
              }).start();
          }

          latch.await(); // 主线程等待所有任务完成
          System.out.println("All tasks finished");
      }
  }
  ```

#### 2. **CyclicBarrier**
- **原理**：让一组线程相互等待到达屏障点。
- **示例**：
  ```java
  public class CyclicBarrierDemo {
      public static void main(String[] args) {
          CyclicBarrier barrier = new CyclicBarrier(3, () -> {
              System.out.println("All threads reached the barrier");
          });

          for(int i=0; i<3; i++) {
              new Thread(() -> {
                  try {
                      barrier.await(); // 等待其他线程
                  } catch (Exception e) { /* 处理异常 */ }
              }).start();
          }
      }
  }
  ```

#### 3. **Semaphore**
- **原理**：控制同时访问资源的线程数。
- **示例**（限制数据库连接数）：
  ```java
  public class SemaphoreDemo {
      private final Semaphore semaphore = new Semaphore(5); // 允许5个并发

      public void accessDatabase() {
          try {
              semaphore.acquire();
              // 访问数据库
          } finally {
              semaphore.release();
          }
      }
  }
  ```

### 四、通信方式对比
| **机制**               | **适用场景**                      | **优点**                      | **缺点**                      |
|------------------------|----------------------------------|-------------------------------|-------------------------------|
| `synchronized + wait/notify` | 需要精细控制同步逻辑       | 灵活可控                     | 需手动处理锁和唤醒机制        |
| `BlockingQueue`        | 生产者-消费者模型                | 解耦生产消费，自动阻塞       | 需要管理队列容量              |
| `CountDownLatch`       | 等待多个子任务完成               | 简单直观                     | 一次性使用，不可重置          |
| `CyclicBarrier`        | 多阶段任务同步                   | 可重复使用                   | 需处理屏障点逻辑              |
| `Semaphore`            | 资源池管理（如连接池）           | 灵活控制并发数               | 需正确管理许可证获取/释放     |

---

### 五、最佳实践
1. **优先选择高层工具**：如`BlockingQueue`、`CountDownLatch`等，减少手动同步的复杂性。
2. **避免忙等待（Busy Waiting）**：用`wait()`或阻塞方法替代循环检查标志位，节省CPU资源。
3. **明确锁范围**：同步块尽量只包含必要代码，减少锁竞争。
4. **处理中断**：所有阻塞操作（如`await()`、`take()`）应正确处理`InterruptedException`。

---

### 总结
线程间通信需根据具体场景选择合适机制：
- **简单协调**：`synchronized + wait/notify`或`volatile`
- **生产消费模型**：`BlockingQueue`
- **多线程协作**：`CountDownLatch`/`CyclicBarrier`
- **资源控制**：`Semaphore`

正确使用这些机制能有效提升程序并发性能，同时避免死锁和资源竞争问题。
