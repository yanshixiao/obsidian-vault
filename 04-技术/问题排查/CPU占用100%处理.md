排查CPU占用100%的问题可以按照以下步骤使用`top`和`jstack`工具：

---

**1. 定位高CPU占用的进程**
使用 `top` 命令：
```bash
top
```
• 按 `P` 键：按CPU使用率排序，找到占用率最高的进程（通常是红色或标红的进程）。

• 记录进程PID：例如，发现PID为 `1234` 的Java进程占用CPU极高。


---

**2. 定位进程内高CPU占用的线程**
使用 `top` 的线程模式：
```bash
top -H -p <PID>
```
• 将 `<PID>` 替换为实际进程ID（如 `1234`）。

• 按 `P` 键：按CPU使用率排序，找到该进程内最耗CPU的线程（记录其线程ID，即 `TID`，十进制）。


---

**3. 将线程ID转换为十六进制**
```bash
printf "%x\n" <TID>
```
• 例如，线程ID `5678` 转换为十六进制为 `162e`。


---

**4. 导出Java线程堆栈信息**
使用 `jstack` 命令：
```bash
jstack <PID> > thread_dump.txt
```
• 将 `<PID>` 替换为实际进程ID，输出保存到文件 `thread_dump.txt`。


---

**5. 分析线程堆栈**
在 `thread_dump.txt` 中搜索十六进制线程ID（如 `nid=0x162e`）：
• 关键状态：关注 `RUNNABLE` 状态的线程（表示正在运行或就绪）。

• 典型问题：

  • 死循环：堆栈中同一方法反复出现。

  • 锁竞争：线程卡在 `BLOCKED` 状态。

  • 频繁GC：`Full GC` 日志或 `GC` 相关线程占用高。


---

**6. 验证与修复**
• 代码检查：根据堆栈中的类名和方法名，检查对应代码是否存在逻辑问题（如无限循环、复杂计算）。

• 工具辅助：使用 `jvisualvm`、`async-profiler` 或 `async-profiler` 进一步分析CPU热点。


---

**补充说明**
• 非Java进程：若非Java应用，改用 `gdb` 或 `perf` 工具。

• 系统级问题：检查是否是内核线程（如 `kworker`）或病毒进程导致。

• 多核CPU：单线程可能无法占满全部CPU，需确认是否多线程并行问题。


---

通过以上步骤，可以精准定位到导致CPU过载的代码位置，进而优化或修复问题。
