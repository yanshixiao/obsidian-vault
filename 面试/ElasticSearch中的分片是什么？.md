### **Elasticsearch 中的分片（Shard）**
分片是 Elasticsearch 实现分布式存储和计算的核心机制，用于将索引拆分为多个独立的数据单元，分散存储在不同节点上，以支持海量数据的高效处理和高可用性。

---

### **一、分片的类型**
#### **1. 主分片（Primary Shard）**
• **作用**：  
  • 存储索引的部分数据（数据水平切分）。  
  • 处理写入请求（新增、更新、删除文档）。  
• **特性**：  
  • 主分片数在索引创建时定义（默认为 `1`），后续不可修改。  
  • 每个文档属于且仅属于一个主分片，通过哈希算法（如 `_routing`）决定存储位置。  

#### **2. 副本分片（Replica Shard）**
• **作用**：  
  • 提供数据冗余（高可用性）：副本分片是主分片的完整拷贝，主分片故障时可自动升级为主分片。  
  • 提升查询性能：副本分片可处理读请求，分担主分片负载。  
• **特性**：  
  • 副本分片数可动态调整（默认 `1`）。  
  • 副本分片与主分片不会分配在同一节点（防止单点故障）。  

---

### **二、分片的核心价值**
#### **1. 水平扩展（Horizontal Scaling）**
• 通过增加节点和分片，实现存储容量和计算能力的线性扩展。  
• **示例**：一个 100GB 的索引，拆分为 5 个分片 → 每个分片约 20GB，分散到多个节点。  

#### **2. 高并发处理**
• 并行化操作：查询和写入可同时作用于多个分片，提升吞吐量。  
• **示例**：搜索请求被广播到所有分片，各分片独立计算后合并结果。  

#### **3. 容错性（Fault Tolerance）**
• 副本分片机制确保数据不丢失，服务持续可用。  
• **示例**：主分片故障时，副本分片自动接管。  

---

### **三、分片的工作原理**
#### **1. 分片的路由（Routing）**
• 文档存储到哪个主分片由以下公式决定：  
  \[
  \text{shard_num} = \text{hash}(\text{routing}) \% \text{num_primary_shards}
  \]
  • `routing`：默认使用文档 `_id`，可自定义（如用户ID）。  
  • `num_primary_shards`：主分片数。  

**示例**：  
• 索引主分片数为 `3`，文档 `_id` 为 `1` → `hash(1) % 3 = 0` → 存储到分片 0。  

#### **2. 分片分配策略**
• **均衡分配**：Elasticsearch 自动将分片均匀分配到可用节点。  
• **控制分配**：通过 `Shard Allocation Awareness` 或手动规则指定分片位置。  

#### **3. 分片状态**
• **未分配（Unassigned）**：分片未分配到任何节点（可能因节点不足或配置限制）。  
• **已分配（Started）**：分片正常服务。  
• **迁移中（Relocating）**：分片正在节点间迁移（如节点故障恢复后重新平衡）。  

---

### **四、分片的最佳实践**
#### **1. 分片数规划**
• **单分片大小**：推荐 **10-50GB**（日志类数据可放宽至 100GB）。  
• **主分片数公式**：  
  \[
  \text{主分片数} = \frac{\text{预期总数据量}}{\text{单分片目标大小}}
  \]
  • **示例**：预期数据量 500GB → 主分片数设为 `10`（每个分片 50GB）。  

#### **2. 副本数设置**
• **生产环境**：至少 `1` 个副本（高可用性）。  
• **写入密集型场景**：可临时减少副本数（如导入数据时设为 `0`，完成后再恢复）。  

#### **3. 避免分片过多**
• **问题**：分片过多会增加元数据开销，降低查询性能。  
• **建议**：单个索引分片数不超过节点数的 **5-10 倍**。  

---

### **五、常见问题与解决方案**
#### **1. 分片未分配**
• **原因**：节点资源不足（磁盘、内存）、分配规则限制。  
• **解决**：  
  ```bash
  # 查看未分配原因
  GET _cluster/allocation/explain

  # 强制分配分片（谨慎操作）
  POST _cluster/reroute
  {
    "commands": [
      { "allocate_stale_primary": { "index": "logs", "shard": 0, "node": "node-1" } }
    ]
  }
  ```

#### **2. 分片不均（Hotspot）**
• **原因**：节点故障恢复后分片集中到少数节点。  
• **解决**：  
  ```bash
  # 启用自动分片均衡（默认开启）
  PUT _cluster/settings
  {
    "transient": { "cluster.routing.rebalance.enable": "all" }
  }
  ```

#### **3. 分片过大**
• **解决**：  
  • 通过 `Reindex API` 拆分索引（需重建索引）。  
  • 使用 `ILM` 按时间滚动索引（适用于时序数据）。  

---

### **六、总结**
分片是 Elasticsearch 分布式能力的基石，通过合理规划分片数和副本数，可显著提升集群的 **扩展性、吞吐量和容错性**。核心原则包括：
• **控制分片大小**：避免过大或过小。  
• **分离冷热数据**：结合 ILM 优化存储成本。  
• **监控分片状态**：及时处理未分配或异常分片。
