### 事务隔离级别及MySQL默认隔离级别详解

---

#### **一、事务的四种隔离级别**

事务隔离级别定义了多个并发事务之间的可见性和影响范围，从低到高分为以下四种：

| **隔离级别**            | **脏读** | **不可重复读** | **幻读** | **典型应用场景**                     |
|-------------------------|----------|----------------|----------|--------------------------------------|
| **READ UNCOMMITTED**    | ❌       | ❌             | ❌       | 几乎不用，仅用于极低一致性需求       |
| **READ COMMITTED**      | ✅       | ❌             | ❌       | 多数数据库默认（如Oracle、PostgreSQL）|
| **REPEATABLE READ**     | ✅       | ✅             | ❌*      | **MySQL默认级别**，平衡一致性与性能  |
| **SERIALIZABLE**        | ✅       | ✅             | ✅       | 高一致性需求，但性能最差             |

> **注**：  
> - ✅ 表示 **解决** 该问题；❌ 表示 **未解决**。  
> - *MySQL的`REPEATABLE READ`通过 **MVCC（多版本并发控制）** 和 **间隙锁（Gap Lock）** 可部分避免幻读。

---

#### **二、各隔离级别的核心问题**

1. **脏读（Dirty Read）**  
   事务A读取了事务B **未提交** 的数据，若事务B回滚，事务A读取的数据无效。

2. **不可重复读（Non-Repeatable Read）**  
   事务A多次读取同一数据，由于事务B的 **修改并提交**，导致结果不一致。

3. **幻读（Phantom Read）**  
   事务A多次查询同一范围，事务B **插入/删除** 了该范围内的数据并提交，导致结果的行数变化。

---

#### **三、MySQL的默认隔离级别**

- **默认级别**：`REPEATABLE READ`（可重复读）。  
- **原因**：  
  - 通过 **MVCC** 机制实现快照读（Snapshot Read），确保同一事务内多次读取结果一致。  
  - 通过 **Next-Key Lock**（记录锁 + 间隙锁）减少幻读风险。  
  - 在保证一致性的同时，提供较高的并发性能。

---

#### **四、如何查看和修改MySQL隔离级别**

1. **查看当前隔离级别**：  
   ```sql
   SELECT @@transaction_isolation;  -- MySQL 8.0+
   -- 或
   SELECT @@tx_isolation;          -- MySQL 5.x
   ```

2. **修改会话级隔离级别**：  
   ```sql
   SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
   ```

3. **修改全局级隔离级别**（需重启生效）：  
   ```sql
   SET GLOBAL TRANSACTION ISOLATION LEVEL REPEATABLE READ;
   ```

---

#### **五、不同隔离级别的实现机制**

| **隔离级别**      | **实现原理**                                                                 |
|-------------------|-----------------------------------------------------------------------------|
| **READ COMMITTED**| 每次查询生成新快照（Read View），读取其他事务已提交的数据。                  |
| **REPEATABLE READ**| 事务首次查询时生成快照，后续读取复用该快照（通过Undo Log实现多版本）。      |
| **SERIALIZABLE**  | 所有读操作加共享锁，写操作加排他锁，完全串行执行。                          |

---

#### **六、隔离级别的选择建议**

| **场景**                  | **推荐隔离级别**     | **理由**                                                                 |
|---------------------------|---------------------|-------------------------------------------------------------------------|
| 高并发读写，容忍部分幻读   | `REPEATABLE READ`   | MySQL默认，MVCC优化性能，间隙锁减少幻读。                               |
| 强一致性，接受性能损失     | `SERIALIZABLE`      | 金融交易等场景，确保绝对一致性。                                        |
| 兼容其他数据库（如Oracle） | `READ COMMITTED`    | 与多数数据库默认行为一致。                                              |

---

#### **七、示例：MySQL如何避免幻读**

在`REPEATABLE READ`级别下，若事务A执行范围查询：  
```sql
-- 事务A
BEGIN;
SELECT * FROM users WHERE age > 20;  -- 首次查询，生成Read View
```
此时事务B插入`age=25`的数据并提交：  
```sql
-- 事务B
INSERT INTO users (age) VALUES (25);
COMMIT;
```
- **事务A的后续查询**：  
  仍只能看到首次查询时的快照数据，**避免幻读**（若使用`SELECT ... FOR UPDATE`会触发间隙锁，直接阻止事务B的插入）。

---

#### **八、总结**

- **事务隔离级别** 是数据库并发控制的基石，需在 **性能** 与 **一致性** 之间权衡。  
- **MySQL默认使用`REPEATABLE READ`**，通过MVCC和锁机制平衡了多数场景的需求。
