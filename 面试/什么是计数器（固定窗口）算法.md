计数器（固定窗口）算法是一种简单直观的限流算法，通过统计固定时间窗口内的请求数量来实现限流。以下是其核心原理、优缺点及 Java 实现示例：

---

### **核心原理**
1. **时间窗口划分**：将时间划分为固定长度的窗口（如 **1秒**、**1分钟**）。  
2. **计数器统计**：每个窗口内维护一个计数器，统计该时间段内的请求数量。  
3. **阈值判断**：若当前窗口的请求数超过预设阈值，则拒绝后续请求；窗口结束时重置计数器。  

**流程示例**：  
• 设定阈值：每秒最多处理 **100个请求**。  
• 窗口划分：每 **1秒** 为一个窗口（如 `00:00:00` ~ `00:00:01`）。  
• 请求处理：  
  • 若窗口内请求数 ≤100：允许处理。  
  • 若请求数 >100：触发限流，拒绝请求。  
• 窗口结束时，计数器归零，进入下一个窗口周期。

---

### **优缺点分析**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **实现简单**：逻辑清晰，代码易实现。  | 1. **窗口边界突发问题**：相邻窗口交接时可能瞬间通过两倍阈值流量（如第1秒最后100ms和第2秒前100ms累计200请求）。  |
| 2. **内存开销低**：只需维护计数器和时间戳。 | 2. **流量不够平滑**：无法精确控制单位时间内的流量均匀分布。  |

---

### **Java 实现示例**
```java
import java.util.concurrent.atomic.AtomicLong;

public class FixedWindowCounter {
    private final int maxRequests;      // 窗口内允许的最大请求数
    private final long windowMillis;   // 窗口时间（毫秒）
    private final AtomicLong counter = new AtomicLong(0); // 计数器
    private volatile long windowStart = System.currentTimeMillis(); // 窗口起始时间

    public FixedWindowCounter(int maxRequests, long windowMillis) {
        this.maxRequests = maxRequests;
        this.windowMillis = windowMillis;
    }

    public boolean allow() {
        long currentTime = System.currentTimeMillis();
        // 如果当前时间超过窗口时间，重置计数器和窗口起始时间
        if (currentTime - windowStart > windowMillis) {
            synchronized (this) {
                if (currentTime - windowStart > windowMillis) {
                    windowStart = currentTime;
                    counter.set(0);
                }
            }
        }
        // 检查当前窗口内请求数是否超过阈值
        return counter.incrementAndGet() <= maxRequests;
    }
}
```

**使用示例**：  
```java
public class Main {
    public static void main(String[] args) {
        // 每秒最多处理100个请求
        FixedWindowCounter limiter = new FixedWindowCounter(100, 1000);
        for (int i = 0; i < 150; i++) {
            if (limiter.allow()) {
                System.out.println("处理请求 " + i);
            } else {
                System.out.println("请求 " + i + " 被限流");
            }
        }
    }
}
```

### **适用场景**
1. **低频接口限流**：如后台管理系统、低频API。  
2. **简单场景**：对流量精度要求不高，允许短期突发流量的系统。  
3. **快速验证**：在限流需求不复杂时，快速搭建原型。

---

### **改进方案**
• **滑动窗口计数器**：将大窗口拆分为更细粒度的子窗口，提升流量控制的精度。  
• **漏桶/令牌桶算法**：解决突发流量问题，实现流量平滑处理。

---

### **总结**
计数器（固定窗口）算法是限流领域的入门级方案，适合简单场景，但需注意其边界突发问题。在实际生产环境中，建议结合业务需求选择更精细的限流算法（如滑动窗口、令牌桶）。
