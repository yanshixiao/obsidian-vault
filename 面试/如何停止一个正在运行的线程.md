在 Java 中，**停止一个正在运行的线程需要遵循协作式机制**（而非强制终止），因为直接强制终止线程会导致资源未释放、数据不一致等问题。以下是安全停止线程的 4 种核心方法，按优先级排序：

---

### **1. 使用标志位 + 轮询检查（推荐基础方案）**
通过 `volatile` 变量控制线程退出，适合 **非阻塞** 场景。

```java
class MyTask implements Runnable {
    private volatile boolean stopped = false; // 必须用 volatile 保证可见性

    public void stop() {
        this.stopped = true; // 外部调用此方法停止线程
    }

    @Override
    public void run() {
        while (!stopped) { // 轮询检查标志位
            // 执行任务...
        }
        System.out.println("线程安全退出");
    }
}

// 使用示例
MyTask task = new MyTask();
new Thread(task).start();
Thread.sleep(1000);
task.stop(); // 安全停止线程
```

---

### **2. 中断机制（推荐终极方案）**
利用线程的 **中断状态** 和 **阻塞方法抛异常** 特性，适合处理阻塞操作（如 `sleep()`/`wait()`/`IO`）。

```java
class InterruptTask implements Runnable {
    @Override
    public void run() {
        while (!Thread.currentThread().isInterrupted()) { // 检查中断状态
            try {
                // 模拟阻塞操作（如 Thread.sleep、Socket.read 等）
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                // 捕获中断异常后，需重置中断状态（规范做法）
                Thread.currentThread().interrupt(); 
                System.out.println("线程被中断，退出循环");
                break; // 退出循环终止线程
            }
        }
    }
}

// 使用示例
Thread thread = new Thread(new InterruptTask());
thread.start();
Thread.sleep(2000);
thread.interrupt(); // 发起中断请求
```

### **3. 关闭线程池（ExecutorService 场景）**
若使用线程池管理线程，通过 `shutdown()` 或 `shutdownNow()` 停止。

```java
ExecutorService executor = Executors.newFixedThreadPool(2);
executor.submit(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        // 执行任务...
    }
});

// 优雅关闭：等待已提交任务完成
executor.shutdown(); 

// 强制关闭：尝试中断所有运行中的线程
executor.shutdownNow(); 
```

---

### **4. 守护线程（自动终止）**
将线程设为守护线程（`setDaemon(true)`），当 JVM 中只剩守护线程时自动退出。

```java
Thread daemonThread = new Thread(() -> {
    while (true) {
        // 执行后台任务...
    }
});
daemonThread.setDaemon(true); // 设置为守护线程
daemonThread.start();
```

---

### **为什么不能强制停止线程？**
- **废弃的 `Thread.stop()`**  
  该方法会立即释放线程持有的所有锁，可能导致对象状态不一致（如银行转账中途被终止）。
- **资源泄漏风险**  
  强制终止可能导致文件句柄、网络连接等资源未关闭。
- **破坏原子性**  
  线程可能正在执行关键操作（如写入数据库），突然终止导致数据损坏。

---

### **最佳实践总结**
| 场景                      | 方案                          | 关键点                                      |
|--------------------------|------------------------------|-------------------------------------------|
| 简单非阻塞任务             | 标志位 + `volatile`          | 确保标志可见性，定期轮询检查                 |
| 涉及阻塞操作（如 I/O、sleep）| 中断机制 + `InterruptedException` | 捕获异常后重置中断状态，退出循环            |
| 线程池管理                | `shutdown()`/`shutdownNow()` | 根据需求选择优雅关闭或强制中断              |
| 后台服务线程              | 守护线程                      | JVM 退出时自动终止，无需手动干预            |

**关键原则**：通过协作让线程自行退出，避免强制终止！
