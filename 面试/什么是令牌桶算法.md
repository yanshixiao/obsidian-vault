令牌桶算法（Token Bucket Algorithm）是一种广泛使用的限流算法，通过动态生成令牌控制请求速率，**允许突发流量**的同时保证长期平均速率稳定。以下是其核心原理、实现方式及实际应用场景：

---

### **一、核心原理**
1. **令牌生成**：以 **固定速率** 向桶中添加令牌（Token）。  
2. **令牌获取**：请求到达时，从桶中获取令牌，获取成功则处理，否则触发限流。  
3. **桶容量**：桶的最大令牌数，允许 **短期突发流量**（如桶满时瞬间处理大量请求）。

#### **关键参数**
| **参数**        | **说明**                          | **示例**              |
|-----------------|-----------------------------------|----------------------|
| 桶容量（Capacity） | 桶能容纳的最大令牌数               | 1000个令牌            |
| 令牌生成速率（Rate） | 每秒生成的令牌数                   | 10令牌/秒             |

---

### **二、算法流程**
```plaintext
1. 令牌生成 → 以固定速率向桶中添加令牌（不超过桶容量）  
2. 请求到达 → 检查桶中是否有令牌  
   ↓  
3. 若有令牌 → 取走令牌并处理请求  
   ↓  
4. 若无令牌 → 触发限流（拒绝请求或等待）  
```

---

### **三、Java实现示例**
#### **基础版本（单线程）**
```java
public class TokenBucketLimiter {
    private final long capacity;      // 桶容量
    private final long refillRate;    // 令牌生成速率（令牌/秒）
    private long tokens;               // 当前令牌数
    private long lastRefillTime;       // 上次补充令牌的时间

    public TokenBucketLimiter(long capacity, long refillRate) {
        this.capacity = capacity;
        this.refillRate = refillRate;
        this.tokens = capacity;
        this.lastRefillTime = System.currentTimeMillis();
    }

    public synchronized boolean allow() {
        refillTokens(); // 补充令牌
        if (tokens > 0) {
            tokens--;
            return true;
        }
        return false;
    }

    private void refillTokens() {
        long now = System.currentTimeMillis();
        long elapsed = now - lastRefillTime;
        // 计算应补充的令牌数
        long newTokens = elapsed * refillRate / 1000;
        if (newTokens > 0) {
            tokens = Math.min(capacity, tokens + newTokens);
            lastRefillTime = now;
        }
    }
}

// 使用示例：每秒生成10个令牌，桶容量1000
TokenBucketLimiter limiter = new TokenBucketLimiter(1000, 10);
if (limiter.allow()) {
    // 处理请求
} else {
    // 限流
}
```

#### **高并发优化版（Atomic变量）**
```java
import java.util.concurrent.atomic.AtomicLong;

public class ConcurrentTokenBucket {
    private final long capacity;
    private final long refillRate;
    private final AtomicLong tokens;
    private final AtomicLong lastRefillTime;

    public ConcurrentTokenBucket(long capacity, long refillRate) {
        this.capacity = capacity;
        this.refillRate = refillRate;
        this.tokens = new AtomicLong(capacity);
        this.lastRefillTime = new AtomicLong(System.currentTimeMillis());
    }

    public boolean allow() {
        refillTokens();
        while (true) {
            long currentTokens = tokens.get();
            if (currentTokens <= 0) return false;
            if (tokens.compareAndSet(currentTokens, currentTokens - 1)) {
                return true;
            }
        }
    }

    private void refillTokens() {
        long now = System.currentTimeMillis();
        long oldTime = lastRefillTime.get();
        if (now - oldTime < 1000) return; // 未到补充周期
        if (lastRefillTime.compareAndSet(oldTime, now)) {
            long newTokens = (now - oldTime) * refillRate / 1000;
            tokens.updateAndGet(current -> Math.min(capacity, current + newTokens));
        }
    }
}
```

### **四、优缺点分析**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **允许突发流量**：桶满时可处理大量请求。 | 1. **突发可能压垮下游**：需结合下游容量使用。 |
| 2. **平滑限流**：长期平均速率稳定。      | 2. **实现复杂度较高**：需维护令牌生成状态。  |
| 3. **灵活配置**：可调整速率和容量。      | 3. **时钟依赖**：依赖系统时间计算令牌补充。  |

---

### **五、应用场景**
1. **API网关限流**：如Google Cloud Endpoints、Kong。  
2. **高并发接口**：电商秒杀、抢购活动等突发流量场景。  
3. **网络流量控制**：路由器或防火墙中平滑数据包传输。  

---

### **六、与漏桶算法对比**
| **维度**       | **令牌桶算法**                      | **漏桶算法**                        |
|----------------|-----------------------------------|-------------------------------------|
| **流量特性**    | 允许突发流量（桶内令牌可累积）         | 严格平滑流量（恒定速率）                |
| **核心控制点**  | 控制令牌生成速率（请求处理速率可变）     | 控制漏水速率（请求处理速率恒定）          |
| **适用场景**    | 需要兼顾突发与稳定的场景（如API网关）    | 严格流量整形场景（如音视频流传输）         |

---

### **七、生产建议**
1. **预生成令牌**：避免每次请求都计算令牌补充，减少性能开销。  
2. **结合熔断降级**：在限流后返回友好提示或默认响应。  
3. **分布式扩展**：通过Redis实现分布式令牌桶（使用Lua脚本保证原子性）。  

---

### **总结**
令牌桶算法通过 **动态生成令牌** 和 **允许突发流量** 的特性，成为高并发系统中限流的主流方案。尽管实现复杂度较高，但其灵活性和对突发流量的友好支持，使其在电商、金融等领域广泛应用。实际开发中建议直接使用成熟库（如 **Guava RateLimiter**）以减少维护成本。
