### 一、**固定窗口计数器（Fixed Window Counter）**
#### **原理**
将时间划分为固定窗口（如1秒），统计窗口内的请求数，超过阈值则拒绝请求。  
**缺点**：窗口切换时可能突发两倍阈值流量。  
**适用场景**：低频接口或简单限流需求。

#### **Java 实现**
```java
import java.util.concurrent.atomic.AtomicLong;

public class FixedWindowLimiter {
    private final long windowMillis;  // 窗口时间（毫秒）
    private final int maxRequests;    // 窗口内允许的最大请求数
    private final AtomicLong counter = new AtomicLong(0);
    private volatile long windowStart = System.currentTimeMillis();

    public FixedWindowLimiter(int maxRequests, long windowMillis) {
        this.maxRequests = maxRequests;
        this.windowMillis = windowMillis;
    }

    public boolean allow() {
        long now = System.currentTimeMillis();
        // 如果超过窗口时间，重置计数器和窗口起始时间
        if (now - windowStart > windowMillis) {
            synchronized (this) {
                if (now - windowStart > windowMillis) {
                    windowStart = now;
                    counter.set(0);
                }
            }
        }
        return counter.incrementAndGet() <= maxRequests;
    }
}

// 使用示例：每秒最多处理100个请求
FixedWindowLimiter limiter = new FixedWindowLimiter(100, 1000);
if (limiter.allow()) {
    // 处理请求
} else {
    // 限流
}
```

### 二、**滑动窗口计数器（Sliding Window Counter）**
#### **原理**
将时间划分为更细粒度的子窗口（如100ms），统计滑动窗口内的总请求数。  
**优点**：解决固定窗口的边界突发问题。  
**适用场景**：高精度限流（如API网关）。

#### **Java 实现**
```java
import java.util.LinkedList;
import java.util.Queue;

public class SlidingWindowLimiter {
    private final int maxRequests;    // 滑动窗口内允许的最大请求数
    private final long windowMillis; // 窗口时间（毫秒）
    private final Queue<Long> timestamps = new LinkedList<>(); // 存储请求时间戳

    public SlidingWindowLimiter(int maxRequests, long windowMillis) {
        this.maxRequests = maxRequests;
        this.windowMillis = windowMillis;
    }

    public synchronized boolean allow() {
        long now = System.currentTimeMillis();
        // 移除窗口外的旧时间戳
        while (!timestamps.isEmpty() && now - timestamps.peek() > windowMillis) {
            timestamps.poll();
        }
        // 检查当前窗口内请求数
        if (timestamps.size() >= maxRequests) {
            return false;
        }
        timestamps.add(now);
        return true;
    }
}
```

### 三、**漏桶算法（Leaky Bucket）**
#### **原理**
以恒定速率处理请求，桶满则拒绝新请求。  
**优点**：流量绝对平滑；**缺点**：无法应对突发流量。  
**适用场景**：稳定速率处理（如消息队列消费）。

#### **Java 实现**
```java
public class LeakyBucketLimiter {
    private final long capacity;      // 桶容量
    private final long rateMillis;    // 漏水速率（毫秒/请求）
    private long water = 0;           // 当前水量
    private long lastLeakTime = System.currentTimeMillis();

    public LeakyBucketLimiter(int capacity, int ratePerSecond) {
        this.capacity = capacity;
        this.rateMillis = 1000 / ratePerSecond; // 计算每请求所需时间
    }

    public synchronized boolean allow() {
        long now = System.currentTimeMillis();
        // 计算漏水量
        long elapsed = now - lastLeakTime;
        long leaks = elapsed / rateMillis;
        water = Math.max(0, water - leaks);
        lastLeakTime = now;
        // 检查桶容量
        if (water < capacity) {
            water++;
            return true;
        }
        return false;
    }
}
```

### 四、**令牌桶算法（Token Bucket）**
#### **原理**
以固定速率生成令牌，请求需获取令牌才能处理，允许短期突发流量。  
**优点**：兼顾平滑限流与突发处理。  
**适用场景**：高并发场景（如电商秒杀）。

#### **Java 实现**
```java
public class TokenBucketLimiter {
    private final long capacity;     // 桶容量
    private final long refillRate;   // 令牌生成速率（令牌/秒）
    private long tokens;             // 当前令牌数
    private long lastRefillTime = System.currentTimeMillis();

    public TokenBucketLimiter(long capacity, long refillRate) {
        this.capacity = capacity;
        this.refillRate = refillRate;
        this.tokens = capacity;
    }

    public synchronized boolean allow() {
        refillTokens();
        if (tokens > 0) {
            tokens--;
            return true;
        }
        return false;
    }

    // 补充令牌
    private void refillTokens() {
        long now = System.currentTimeMillis();
        long elapsed = now - lastRefillTime;
        long newTokens = elapsed * refillRate / 1000;
        if (newTokens > 0) {
            tokens = Math.min(capacity, tokens + newTokens);
            lastRefillTime = now;
        }
    }
}
```

### 五、**并发数限流（Semaphore）**
#### **原理**
限制同时处理的请求数量，保护系统资源。  
**适用场景**：数据库连接池、线程池限流。

#### **Java 实现**
```java
import java.util.concurrent.Semaphore;

public class ConcurrencyLimiter {
    private final Semaphore semaphore;

    public ConcurrencyLimiter(int maxConcurrent) {
        semaphore = new Semaphore(maxConcurrent);
    }

    public boolean tryAcquire() {
        return semaphore.tryAcquire();
    }

    public void release() {
        semaphore.release();
    }
}

// 使用示例：限制最大并发数为100
ConcurrencyLimiter limiter = new ConcurrencyLimiter(100);
if (limiter.tryAcquire()) {
    try {
        // 处理请求
    } finally {
        limiter.release();
    }
} else {
    // 限流
}
```

### 六、**分布式限流（Redis + Lua）**
#### **原理**
通过Redis的原子操作实现分布式限流，保证跨服务一致性。  
**适用场景**：微服务架构下的统一限流。

#### **Java 实现**
```java
import redis.clients.jedis.Jedis;

public class RedisRateLimiter {
    private final Jedis jedis;
    private final String key;
    private final int maxRequests;
    private final int windowSeconds;

    public RedisRateLimiter(Jedis jedis, String key, int maxRequests, int windowSeconds) {
        this.jedis = jedis;
        this.key = key;
        this.maxRequests = maxRequests;
        this.windowSeconds = windowSeconds;
    }

    public boolean allow() {
        String luaScript = 
            "local current = redis.call('get', KEYS[1])\n" +
            "if current and tonumber(current) >= tonumber(ARGV[1]) then\n" +
            "    return 0\n" +
            "else\n" +
            "    redis.call('incr', KEYS[1])\n" +
            "    redis.call('expire', KEYS[1], ARGV[2])\n" +
            "    return 1\n" +
            "end";
        Long result = (Long) jedis.eval(luaScript, 1, key, 
            String.valueOf(maxRequests), String.valueOf(windowSeconds));
        return result == 1;
    }
}
```

### **选型建议**
| **场景**               | **推荐算法**              | **特点**                         |
|------------------------|--------------------------|----------------------------------|
| 简单低频限流           | 固定窗口计数器            | 实现简单，适合低频接口           |
| 高精度限流             | 滑动窗口计数器            | 解决边界突发问题                 |
| 稳定速率处理           | 漏桶算法                 | 严格平滑流量（如MQ消费）         |
| 允许突发流量           | 令牌桶算法               | 高并发场景（如秒杀）             |
| 资源保护               | 并发数限流（Semaphore）  | 限制线程/连接数                 |
| 分布式系统              | Redis + Lua             | 跨服务统一限流                  |

---

### **总结**
• **固定窗口/滑动窗口**：适用于API限流，滑动窗口精度更高。  
• **漏桶/令牌桶**：漏桶严格限制速率，令牌桶允许突发流量。  
• **并发数限流**：直接保护资源（如数据库连接池）。  
• **分布式限流**：通过Redis保证原子性，适合微服务架构。  

这些示例代码可直接用于项目开发，但生产环境中建议使用成熟库（如 **Guava RateLimiter** 或 **Sentinel**）。
