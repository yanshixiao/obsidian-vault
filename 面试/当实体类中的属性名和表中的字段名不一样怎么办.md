在 MyBatis 中，当实体类的属性名与数据库表的字段名不一致时，可以通过以下方法解决：

---

### **1. 使用 `resultMap` 显式映射**
在 XML 映射文件中定义 `<resultMap>`，明确指定字段名与属性名的对应关系。  
**示例**：
```xml
<resultMap id="userResultMap" type="com.example.User">
    <!-- 主键字段映射 -->
    <id property="id" column="user_id"/>
    <!-- 普通字段映射 -->
    <result property="userName" column="name"/>
    <result property="userEmail" column="email"/>
</resultMap>

<select id="getUser" resultMap="userResultMap">
    SELECT user_id, name, email FROM users WHERE id = #{id}
</select>
```

**优点**：  
- 灵活性高，支持复杂映射（如嵌套对象、集合等）。  
- 可读性强，集中管理映射关系。

**缺点**：  
- 配置稍显繁琐，需为每个不一致的字段单独声明。

---

### **2. 在 SQL 中使用别名（Alias）**
直接在 SQL 查询中为字段设置别名，与实体类属性名保持一致。  
**示例**：
```xml
<select id="getUser" resultType="com.example.User">
    SELECT 
        user_id AS id, 
        name AS userName, 
        email AS userEmail 
    FROM users 
    WHERE id = #{id}
</select>
```

**优点**：  
- 简单快捷，适合少量字段不一致的场景。

**缺点**：  
- 需在每个 SQL 语句中重复编写别名，维护成本高。

---

### **3. 开启自动驼峰命名转换**
如果数据库字段名是下划线格式（如 `user_name`），而实体类属性名是驼峰格式（如 `userName`），可直接开启 MyBatis 的自动驼峰转换功能。  

**配置方式**（在 `mybatis-config.xml` 中）：
```xml
<settings>
    <setting name="mapUnderscoreToCamelCase" value="true"/>
</settings>
```

**示例**：  
- 数据库字段：`user_name` → 自动映射到实体类属性 `userName`。

**优点**：  
- 零配置，符合命名规范时自动生效。  
- 减少冗余代码。

**缺点**：  
- 仅适用于下划线与驼峰格式的转换，不适用于其他命名差异（如 `email` → `userEmail`）。

---

### **4. 使用注解 `@Results` 和 `@Result`**
在接口方法上通过注解直接定义映射关系（需使用 MyBatis 注解开发模式）。  
**示例**：
```java
@Select("SELECT user_id, name, email FROM users WHERE id = #{id}")
@Results({
    @Result(property = "id", column = "user_id"),
    @Result(property = "userName", column = "name"),
    @Result(property = "userEmail", column = "email")
})
User getUserById(Integer id);
```

**优点**：  
- 注解与 SQL 语句集中，适合简单场景。

**缺点**：  
- 注解冗长，复杂映射时代码可读性差。

---

### **总结：如何选择？**
| **场景**                     | **推荐方案**               |
|------------------------------|--------------------------|
| 少量字段不一致               | SQL 别名                 |
| 复杂映射或大量字段不一致     | `resultMap` 显式映射     |
| 符合下划线转驼峰命名规范     | 自动驼峰转换             |
| 注解开发且映射简单           | `@Results` 注解         |

---

### **注意事项**
- **优先使用 `resultMap`**：对于长期维护的项目，显式映射更清晰、可扩展。  
- **避免硬编码别名**：若频繁修改字段名，别名可能导致 SQL 散落在多处，维护困难。  
- **谨慎开启驼峰转换**：需确保团队遵守命名规范，避免意外映射错误。
