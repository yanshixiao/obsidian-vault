责任链模式（**Chain of Responsibility Pattern**）是一种行为型设计模式，**允许将请求沿着处理链传递，直到有对象处理它为止**。每个处理者均可决定是否处理请求或将其传递给链中的下一个处理者。该模式解耦了请求发送者和接收者，常用于多级审批、事件拦截、过滤器链等场景。

---

### **核心思想**
1. **链式处理**：多个处理者组成一条链，依次尝试处理请求。
2. **动态职责分配**：运行时动态调整链中处理者的顺序或数量。
3. **解耦**：发送者无需知道具体处理者，只需将请求发送到链的起点。

---

### **模式结构**
| **角色**               | **说明**                          |
|------------------------|-----------------------------------|
| **处理者接口（Handler）**  | 定义处理请求的方法，并持有下一个处理者的引用。 |
| **具体处理者（Concrete Handler）** | 实现处理逻辑，决定是否处理请求或传递。 |
| **客户端（Client）**       | 组装处理链，并向链头发送请求。          |

---

### **Java 实现示例：多级审批流程**
#### **1. 处理者接口**
```java
public abstract class Approver {
    protected Approver nextApprover; // 下一个处理者

    public void setNextApprover(Approver nextApprover) {
        this.nextApprover = nextApprover;
    }

    public abstract void processRequest(PurchaseRequest request);
}
```

#### **2. 具体处理者（不同级别审批人）**
```java
// 部门经理：审批金额 <= 5000
public class Manager extends Approver {
    @Override
    public void processRequest(PurchaseRequest request) {
        if (request.getAmount() <= 5000) {
            System.out.println("Manager approves: " + request.getPurpose());
        } else if (nextApprover != null) {
            nextApprover.processRequest(request); // 转交上级
        }
    }
}

// 总监：审批金额 <= 10000
public class Director extends Approver {
    @Override
    public void processRequest(PurchaseRequest request) {
        if (request.getAmount() <= 10000) {
            System.out.println("Director approves: " + request.getPurpose());
        } else if (nextApprover != null) {
            nextApprover.processRequest(request); // 转交上级
        }
    }
}

// CEO：审批金额 > 10000
public class CEO extends Approver {
    @Override
    public void processRequest(PurchaseRequest request) {
        if (request.getAmount() > 10000) {
            System.out.println("CEO approves: " + request.getPurpose());
        } else {
            System.out.println("Request denied: No approver available.");
        }
    }
}
```

#### **3. 请求对象**
```java
public class PurchaseRequest {
    private String purpose;
    private double amount;

    public PurchaseRequest(String purpose, double amount) {
        this.purpose = purpose;
        this.amount = amount;
    }

    // Getters
    public String getPurpose() { return purpose; }
    public double getAmount() { return amount; }
}
```

#### **4. 客户端组装处理链**
```java
public class Client {
    public static void main(String[] args) {
        // 创建处理者
        Approver manager = new Manager();
        Approver director = new Director();
        Approver ceo = new CEO();

        // 组装责任链：Manager → Director → CEO
        manager.setNextApprover(director);
        director.setNextApprover(ceo);

        // 发送请求
        PurchaseRequest request1 = new PurchaseRequest("Buy laptops", 4000);
        manager.processRequest(request1);  // Manager approves

        PurchaseRequest request2 = new PurchaseRequest("Renew office lease", 15000);
        manager.processRequest(request2);  // CEO approves
    }
}
```

### **应用场景**
1. **多级审批**：如OA系统中的报销审批、请假审批流程。
2. **事件拦截**：如Web框架的过滤器链（Servlet Filter、Spring Security）。
3. **异常处理**：逐级尝试处理异常（如日志、降级、告警）。
4. **日志处理**：日志消息通过不同处理器（控制台、文件、数据库）传递。

---

### **优缺点分析**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **解耦**：请求发送者与处理者解耦。         | 1. **请求可能未被处理**：需确保链的完整性。 |
| 2. **动态扩展**：可动态增减或调整处理链顺序。   | 2. **性能损耗**：长链可能导致处理延迟。     |
| 3. **单一职责**：每个处理者聚焦特定处理逻辑。  |                                   |

---

### **责任链模式 vs 装饰器模式**
| **维度**       | **责任链模式**                      | **装饰器模式**                  |
|----------------|-----------------------------------|---------------------------------|
| **目的**        | 多个处理者依次尝试处理同一请求。         | 动态叠加功能，增强对象行为。          |
| **处理逻辑**    | 每个处理者决定是否处理或传递请求。        | 所有装饰器均执行，共同完成功能。       |
| **典型场景**    | 审批流程、过滤器链。                  | I/O流处理、数据加密/压缩。           |

### **实际应用案例**
1. **Java Servlet Filter**：  
   ```java
   public class AuthFilter implements Filter {
       public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain) {
           if (checkAuth(req)) {
               chain.doFilter(req, res); // 传递到下一个Filter
           } else {
               throw new AuthException();
           }
       }
   }
   ```
2. **Spring Security**：多个安全过滤器组成处理链（如认证、授权、CSRF防护）。
3. **Netty 的 ChannelHandler**：处理网络请求的责任链模型。

---

### **总结**
责任链模式通过 **链式传递请求** 和 **动态分配处理职责**，实现了请求发送者与处理者的解耦。其核心价值在于：
• **灵活调整处理流程**：无需修改代码即可增减处理环节。
• **简化对象职责**：每个处理者仅关注自身逻辑，符合单一职责原则。

在需要多级处理或动态流程控制的场景中（如审批系统、中间件框架），责任链模式是构建灵活、可扩展架构的关键工具。
