代理模式和装饰器模式在代码结构上非常相似（都通过组合对象并实现相同接口），但它们的 **设计意图** 和 **应用场景** 有本质区别。以下是两者的核心区别：

---

### **1. 设计意图**
| **代理模式**                  | **装饰器模式**                  |
|------------------------------|-------------------------------|
| **控制访问**：代理类控制对原始对象的访问（如权限校验、延迟加载、远程调用）。 | **增强功能**：动态为原始对象添加新职责（如日志、缓存、加密）。 |
| **隐藏对象存在**：客户端可能不知道代理背后有原始对象（如远程代理）。 | **透明扩展**：客户端明确知道原始对象，装饰器只是增强其功能。 |

---

### **2. 核心区别**
| **维度**       | **代理模式**                                | **装饰器模式**                          |
|----------------|--------------------------------------------|----------------------------------------|
| **目标对象**    | 代理类通常代理 **一个具体类**（或接口）。       | 装饰器可以叠加 **多个装饰器**，形成链式增强。 |
| **创建时机**    | 代理关系通常在 **编译时确定**（如静态代理）。   | 装饰关系可在 **运行时动态组合**（如嵌套装饰）。 |
| **访问控制**    | 可能限制或过滤对原始对象的访问（如权限代理）。   | 不限制访问，仅扩展功能。                     |
| **是否透明**    | 对客户端不透明（客户端可能感知不到原始对象）。    | 对客户端透明（客户端明确使用装饰后的对象）。     |

---

### **3. 代码示例对比**
#### **代理模式（权限控制）**
```java
// 接口
interface Database {
    void query(String sql);
}

// 原始对象
class RealDatabase implements Database {
    public void query(String sql) {
        System.out.println("Executing: " + sql);
    }
}

// 代理类（权限校验）
class ProxyDatabase implements Database {
    private RealDatabase realDb = new RealDatabase();
    private boolean hasAccess;

    public ProxyDatabase(boolean hasAccess) {
        this.hasAccess = hasAccess;
    }

    @Override
    public void query(String sql) {
        if (!hasAccess) {
            throw new SecurityException("Access denied");
        }
        realDb.query(sql); // 控制访问
    }
}

// 客户端可能不知道RealDatabase的存在
Database db = new ProxyDatabase(true);
db.query("SELECT * FROM users");
```

#### **装饰器模式（功能增强）**
```java
// 接口
interface DataSource {
    void writeData(String data);
}

// 原始对象
class FileDataSource implements DataSource {
    public void writeData(String data) {
        System.out.println("Write to file: " + data);
    }
}

// 装饰器基类
abstract class DataSourceDecorator implements DataSource {
    protected DataSource wrappee;

    public DataSourceDecorator(DataSource source) {
        this.wrappee = source;
    }

    @Override
    public void writeData(String data) {
        wrappee.writeData(data);
    }
}

// 具体装饰器（加密）
class EncryptionDecorator extends DataSourceDecorator {
    public EncryptionDecorator(DataSource source) {
        super(source);
    }

    @Override
    public void writeData(String data) {
        String encryptedData = encrypt(data);
        super.writeData(encryptedData);
    }

    private String encrypt(String data) {
        return "ENCRYPTED(" + data + ")";
    }
}

// 客户端明确使用装饰后的对象
DataSource source = new FileDataSource();
source = new EncryptionDecorator(source); // 动态增强
source.writeData("Hello");
```

---

### **4. 典型应用场景**
| **代理模式**                              | **装饰器模式**                          |
|------------------------------------------|----------------------------------------|
| - 远程代理（如RPC调用）                    | - 动态添加功能（日志、缓存、校验）         |
| - 虚拟代理（延迟加载大对象）                | - Java I/O流（`BufferedInputStream` 装饰 `FileInputStream`） |
| - 保护代理（权限控制）                      | - Spring AOP（通过切面增强方法）          |

---

### **总结**
• **代理模式**：**控制访问**，隐藏原始对象的存在，关注 **访问过程**。  
• **装饰器模式**：**增强功能**，客户端明确使用装饰后的对象，关注 **功能叠加**。  

**关键判断**：  
• 如果目的是 **限制访问** 或 **隐藏实现细节** → 选择代理模式。  
• 如果目的是 **动态添加功能** 且 **保持接口透明** → 选择装饰器模式。
