Nginx服务器采用Master-Worker（主-工作）进程架构，这种设计使其能够高效处理高并发请求，同时保持稳定性和可扩展性。以下是Master进程和Worker进程的具体职责和特点：

---

### **1. Master进程**
- **核心职责**：
  - **管理Worker进程**：启动、停止或重新加载Worker进程。
  - **读取配置**：解析并验证Nginx配置文件（`nginx.conf`）。
  - **监听信号**：接收管理员命令（如重载配置、平滑升级）。
  - **维护进程树**：监控Worker进程状态，自动重启崩溃的Worker。

- **特点**：
  - **单实例运行**：一个Nginx服务只有一个Master进程。
  - **不处理请求**：专注于管理任务，不参与客户端请求处理。
  - **权限要求**：通常以`root`用户启动，以便绑定低端口（如80、443）。

- **常用操作**：
  ```bash
  # 重载配置（无缝生效）
  nginx -s reload

  # 平滑升级Nginx版本
  nginx -s upgrade
  ```

---

### **2. Worker进程**
- **核心职责**：
  - **处理客户端请求**：监听端口（如HTTP 80/HTTPS 443），接收并响应请求。
  - **高效并发模型**：基于事件驱动（如`epoll`、`kqueue`）和非阻塞I/O，单进程可处理数千并发连接。
  - **独立运行**：每个Worker进程相互隔离，避免共享资源竞争。

- **特点**：
  - **多实例运行**：数量由`worker_processes`配置决定，通常等于CPU核心数。
  - **低资源消耗**：每个连接仅需约2.5KB内存。
  - **绑定CPU核心**：通过`worker_cpu_affinity`配置提升性能。

- **配置示例**：
  ```nginx
  # 设置Worker进程数与CPU绑定（4核CPU）
  worker_processes 4;
  worker_cpu_affinity 0001 0010 0100 1000;
  ```

---

### **3. Master与Worker协作流程**
1. **启动阶段**：
   - Master进程读取配置文件，检查语法。
   - 根据`worker_processes`创建指定数量的Worker进程。

2. **请求处理**：
   - Worker进程监听端口，通过事件循环处理连接。
   - 每个Worker独立处理请求（静态文件、反向代理等）。

3. **配置重载**：
   - 执行`nginx -s reload`后，Master启动新Worker进程。
   - 旧Worker进程在处理完现有请求后退出，实现无缝切换。

4. **容错恢复**：
   - 如果某个Worker崩溃，Master会重新启动一个新Worker。

---

### **4. 架构优势**
| **优势**          | **说明**                                                                 |
|-------------------|-------------------------------------------------------------------------|
| **高并发性能**    | 每个Worker独立处理请求，结合事件驱动模型，轻松应对高并发场景。            |
| **资源隔离**      | Worker进程崩溃不影响其他进程，提升系统稳定性。                           |
| **无缝升级**      | 通过信号控制，实现配置重载或版本升级无需停机。                           |
| **多核利用率**    | 多个Worker进程绑定不同CPU核心，充分利用多核计算能力。                    |

---

### **5. 查看进程状态**
通过`ps`命令查看Nginx进程：
```bash
ps -ef | grep nginx
```
输出示例：
```
root      1234     1  0 10:00 ?        00:00:00 nginx: master process /usr/sbin/nginx
nginx     5678  1234  0 10:00 ?        00:00:12 nginx: worker process
nginx     5679  1234  0 10:00 ?        00:00:11 nginx: worker process
```

- **Master进程**：负责全局管理，不处理请求，是Nginx的“大脑”。
