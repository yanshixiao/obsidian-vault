工厂模式（**Factory Pattern**）是一种创建型设计模式，**将对象的创建逻辑封装在工厂类中**，客户端无需直接通过 `new` 实例化对象，而是通过工厂方法获取实例，从而**解耦对象创建与使用**，提高代码的灵活性和可维护性。

---

### **工厂模式的核心思想**
• **职责分离**：将对象的创建过程集中到工厂类，客户端只需关注业务逻辑。
• **扩展性**：新增产品类型时，无需修改客户端代码，只需扩展工厂即可。
• **统一入口**：通过工厂方法统一创建对象，隐藏实现细节。

---

### **工厂模式的三种类型**
| **类型**        | **特点**                                                                 | **适用场景**                     |
|-----------------|-------------------------------------------------------------------------|--------------------------------|
| **简单工厂**     | 一个工厂类根据参数创建不同产品，违反开闭原则（需修改工厂代码新增产品）。                | 产品类型少且不频繁变化的场景。           |
| **工厂方法**     | 每个产品对应一个工厂子类，客户端通过子类工厂创建对象，符合开闭原则。                   | 需要灵活扩展产品类型的场景（如框架设计）。    |
| **抽象工厂**     | 创建一组相关或依赖的产品族，解决多产品体系的创建问题（如不同操作系统的UI组件）。           | 跨平台、跨风格的产品族创建。             |

---

### **Java实现示例**

#### **1. 简单工厂（Simple Factory）**
```java
// 1. 定义产品接口
interface Shape {
    void draw();
}

// 2. 具体产品类
class Circle implements Shape {
    @Override
    public void draw() { System.out.println("Draw a circle"); }
}

class Rectangle implements Shape {
    @Override
    public void draw() { System.out.println("Draw a rectangle"); }
}

// 3. 简单工厂类
class ShapeFactory {
    public static Shape createShape(String type) {
        if ("circle".equalsIgnoreCase(type)) {
            return new Circle();
        } else if ("rectangle".equalsIgnoreCase(type)) {
            return new Rectangle();
        }
        throw new IllegalArgumentException("Invalid shape type");
    }
}

// 4. 客户端调用
public class Client {
    public static void main(String[] args) {
        Shape circle = ShapeFactory.createShape("circle");
        circle.draw(); // 输出: Draw a circle
    }
}
```

#### **2. 工厂方法（Factory Method）**
```java
// 1. 产品接口
interface Transport {
    void deliver();
}

// 2. 具体产品类
class Truck implements Transport {
    @Override
    public void deliver() { System.out.println("Deliver by truck"); }
}

class Ship implements Transport {
    @Override
    public void deliver() { System.out.println("Deliver by ship"); }
}

// 3. 工厂接口
interface TransportFactory {
    Transport createTransport();
}

// 4. 具体工厂类
class TruckFactory implements TransportFactory {
    @Override
    public Transport createTransport() { return new Truck(); }
}

class ShipFactory implements TransportFactory {
    @Override
    public Transport createTransport() { return new Ship(); }
}

// 5. 客户端调用
public class Client {
    public static void main(String[] args) {
        TransportFactory factory = new TruckFactory();
        Transport transport = factory.createTransport();
        transport.deliver(); // 输出: Deliver by truck
    }
}
```

#### **3. 抽象工厂（Abstract Factory）**
```java
// 1. 定义产品族接口
interface Button {
    void render();
}

interface TextField {
    void display();
}

// 2. 具体产品：Windows风格
class WindowsButton implements Button {
    @Override
    public void render() { System.out.println("Render Windows button"); }
}

class WindowsTextField implements TextField {
    @Override
    public void display() { System.out.println("Display Windows text field"); }
}

// 3. 具体产品：Mac风格
class MacButton implements Button {
    @Override
    public void render() { System.out.println("Render Mac button"); }
}

class MacTextField implements TextField {
    @Override
    public void display() { System.out.println("Display Mac text field"); }
}

// 4. 抽象工厂接口
interface GUIFactory {
    Button createButton();
    TextField createTextField();
}

// 5. 具体工厂类
class WindowsFactory implements GUIFactory {
    @Override
    public Button createButton() { return new WindowsButton(); }
    @Override
    public TextField createTextField() { return new WindowsTextField(); }
}

class MacFactory implements GUIFactory {
    @Override
    public Button createButton() { return new MacButton(); }
    @Override
    public TextField createTextField() { return new MacTextField(); }
}

// 6. 客户端调用
public class Client {
    public static void main(String[] args) {
        GUIFactory factory = new MacFactory();
        Button button = factory.createButton();
        TextField textField = factory.createTextField();
        button.render();      // 输出: Render Mac button
        textField.display();  // 输出: Display Mac text field
    }
}
```

### **工厂模式的优缺点**
| **优点**                          | **缺点**                          |
|----------------------------------|----------------------------------|
| 1. **解耦**：分离对象创建与使用，降低耦合度。 | 1. **类数量增加**：每新增一个产品需添加工厂类。 |
| 2. **扩展性强**：新增产品只需扩展工厂，无需修改客户端。 | 2. **复杂度提升**：抽象工厂需管理多类产品。   |
| 3. **统一管理**：集中控制对象的创建逻辑（如单例、缓存）。 |                                 |

---

### **应用场景**
1. **框架设计**：Spring的 `BeanFactory`、MyBatis的 `SqlSessionFactory`。
2. **跨平台开发**：创建不同操作系统的UI组件或文件系统接口。
3. **对象创建复杂**：如需要依赖注入、配置参数或多步骤构造的对象。
4. **产品族管理**：如汽车工厂生产引擎、轮胎等系列组件。

---

### **总结**
工厂模式通过**封装对象创建过程**，使代码更灵活、可维护。  
• **简单工厂**：适用于产品类型少、需求固定的场景。  
• **工厂方法**：通过子类工厂扩展，符合开闭原则。  
• **抽象工厂**：解决多产品族的创建问题，适合跨体系架构。  

在Spring等框架中，工厂模式是IoC（控制反转）和DI（依赖注入）的核心实现基础。实际开发中，应根据业务复杂度选择合适的工厂类型。
