Redis的过期策略和内存淘汰机制是确保高效内存管理的重要组成部分。以下是详细的分步解释：

### **1. 过期策略（键的自动删除）**
Redis通过以下三种策略组合来处理设置了过期时间的键：

#### **a. 惰性删除（Lazy Expiration）**
• **机制**：当客户端尝试访问某个键时，Redis会先检查该键是否已过期。若过期则删除，并返回空值。
• **优点**：对CPU友好，仅在访问时处理，避免不必要的资源消耗。
• **缺点**：可能导致内存浪费（过期键未被及时访问时长期存在）。

#### **b. 定期删除（Periodic Expiration）**
• **机制**：Redis每隔一段时间（默认每秒10次）随机扫描一定数量的设置了过期时间的键，删除其中已过期的键。每次扫描的时长上限为25ms，避免阻塞主线程。
• **流程**：
  1. 从过期字典中随机抽取20个键。
  2. 删除其中已过期的键。
  3. 若超过25%的键过期，则重复步骤1-2。
• **优点**：平衡内存和CPU使用，减少过期键堆积。
• **缺点**：可能存在少量过期键未被及时清理。

#### **c. 定时删除（Timed Expiration）**
• **机制**：为每个键创建独立的定时器，在过期时间到达时立即删除。
• **优点**：内存释放及时。
• **缺点**：高CPU开销（大量键同时过期时影响性能）。
• **实际应用**：Redis**未使用**纯定时删除，因其资源消耗不可控。

### **2. 内存淘汰机制（Memory Eviction）**
当Redis内存使用达到`maxmemory`限制时，根据`maxmemory-policy`配置选择淘汰策略。以下是所有策略及其适用场景：

#### **淘汰策略分类**
| **策略**                | **作用范围**            | **淘汰规则**                                                                 |
|-------------------------|------------------------|----------------------------------------------------------------------------|
| `noeviction`            | 所有写入操作            | 拒绝所有写请求（DEL除外），返回错误（默认策略）。                              |
| `allkeys-lru`           | 所有键                 | 淘汰**最近最少使用（LRU）**的键。                                             |
| `volatile-lru`          | 设置了过期时间的键       | 淘汰**最近最少使用（LRU）**的键（仅从过期键中选择）。                           |
| `allkeys-lfu`           | 所有键                 | 淘汰**最不经常使用（LFU）**的键（Redis 4.0+）。                               |
| `volatile-lfu`          | 设置了过期时间的键       | 淘汰**最不经常使用（LFU）**的键（仅从过期键中选择）。                           |
| `allkeys-random`        | 所有键                 | **随机**淘汰任意键。                                                         |
| `volatile-random`       | 设置了过期时间的键       | **随机**淘汰设置了过期时间的键。                                               |
| `volatile-ttl`          | 设置了过期时间的键       | 淘汰**剩余生存时间（TTL）最短**的键。                                           |

#### **LRU/LFU实现优化**
• **近似LRU（Approximated LRU）**：  
  Redis不维护完整的LRU链表，而是随机抽取5个（可配置）键，淘汰其中最近最久未使用的键。  
  优点：内存开销小（每个键仅需24bit记录时间戳），性能高。
  ```bash
  # 调整LRU采样精度（redis.conf）
  maxmemory-samples 5
  ```

• **LFU（Least Frequently Used）**：  
  基于访问频率淘汰，Redis通过衰减计数器（随时间减少访问次数）和概率筛选（对数化访问次数）实现。  
  配置参数：
  ```bash
  lfu-log-factor 10   # 控制计数器增长难度（越大越难）
  lfu-decay-time 1     # 计数器衰减时间（分钟）
  ```

### **3. 配置建议**
#### **a. 过期策略选择**
• **常规场景**：`惰性删除 + 定期删除`（默认组合）。  
• **实时性要求高**：适当调高定期删除频率（需测试CPU负载）。

#### **b. 内存淘汰策略选择**
| **场景**                     | **推荐策略**             | **说明**                                                                 |
|------------------------------|-------------------------|-------------------------------------------------------------------------|
| 缓存数据，允许丢失            | `allkeys-lru`           | 优先保留最近常用数据。                                                    |
| 持久化数据，需严格保留         | `noeviction`            | 确保数据不丢失，依赖业务层处理写拒绝。                                      |
| 混合数据（部分有过期时间）     | `volatile-lru`          | 仅淘汰过期键，保留持久化数据。                                              |
| 热点数据访问频率差异大         | `allkeys-lfu`           | 按访问频率淘汰（适合长尾分布）。                                            |

#### **c. 配置示例**
```bash
# redis.conf
maxmemory 4gb                     # 最大内存限制
maxmemory-policy allkeys-lru      # 使用LRU淘汰所有键
maxmemory-samples 10              # 提高LRU精度
```

### **4. 监控与调优**
#### **关键指标**
• **内存使用**：  
  ```bash
  INFO memory | grep "used_memory_human\|maxmemory_human"
  ```
• **淘汰键数量**：  
  ```bash
  INFO stats | grep evicted_keys
  ```
• **键过期情况**：  
  ```bash
  INFO keyspace | grep "expires"
  ```

#### **调优工具**
• **redis-cli --hotkeys**：识别高频访问键（需`maxmemory-policy`为LRU/LFU）。  
• **MEMORY USAGE key**：查看特定键的内存占用。

---

### **总结**
Redis通过**惰性删除**和**定期删除**组合管理过期键，避免内存泄漏；内存不足时，根据配置的淘汰策略（如LRU/LFU）释放空间。合理选择策略和参数可显著提升性能与可靠性。
