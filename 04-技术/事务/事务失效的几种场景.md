Spring 事务失效的场景通常与 **代理机制、异常处理、数据库配置、事务传播行为** 等相关。以下是常见失效场景及解决方案：

---

### **一、代理机制导致的事务失效**
#### 1. **同一个类内部方法调用**
• **原因**：Spring 事务基于 AOP 代理实现，**自调用不会触发代理逻辑**，导致 `@Transactional` 失效。
• **示例**：
  ```java
  @Service
  public class UserService {
      public void methodA() {
          methodB(); // 自调用，事务不生效！
      }
      @Transactional
      public void methodB() {
          // 数据库操作
      }
  }
  ```
• **解决方案**：
  • 通过注入代理对象调用（需开启 `exposeProxy`）：
    ```java
    @Autowired
    private UserService self; // 注入自身代理对象
    public void methodA() {
        self.methodB(); // 通过代理调用
    }
    ```
  • 使用 `AopContext.currentProxy()`：
    ```java
    ((UserService) AopContext.currentProxy()).methodB();
    ```

#### 2. **未启用事务管理**
• **原因**：未配置 `@EnableTransactionManagement` 或 XML 中未启用 `<tx:annotation-driven/>`。
• **解决方案**：添加注解或配置。

---

### **二、异常处理不当**
#### 1. **捕获异常未抛出**
• **原因**：事务方法内捕获异常后未重新抛出，Spring 无法感知异常，默认不回滚。
• **示例**：
  ```java
  @Transactional
  public void updateData() {
      try {
          // 数据库操作
      } catch (Exception e) {
          // 捕获异常但未抛出 → 事务不回滚！
      }
  }
  ```
• **解决方案**：抛出异常或手动回滚：
  ```java
  catch (Exception e) {
      TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
  }
  ```

#### 2. **未指定回滚的异常类型**
• **原因**：默认仅对 `RuntimeException` 和 `Error` 回滚，检查型异常（如 `SQLException`）需显式配置。
• **解决方案**：使用 `rollbackFor` 指定回滚的异常：
  ```java
  @Transactional(rollbackFor = Exception.class)
  ```

---

### **三、数据库配置问题**
#### 1. **数据库引擎不支持事务**
• **原因**：如 MySQL 的 `MyISAM` 引擎不支持事务，需使用 `InnoDB`。
• **验证方法**：
  ```sql
  SHOW CREATE TABLE your_table;
  -- 检查 Engine 是否为 InnoDB
  ```
• **解决方案**：修改表引擎：
  ```sql
  ALTER TABLE your_table ENGINE=InnoDB;
  ```

#### 2. **自动提交未关闭**
• **原因**：数据库连接默认自动提交（`autocommit=true`），导致每个 SQL 独立提交。
• **解决方案**：在 Spring 配置中关闭自动提交：
  ```yaml
  spring:
    datasource:
      hikari:
        auto-commit: false # 关闭自动提交
  ```

---

### **四、事务传播行为配置错误**
#### 1. **传播行为导致事务边界不符**
• **示例**：使用 `REQUIRES_NEW` 但外层无事务，可能导致预期外的独立事务。
• **解决方案**：合理选择传播行为（如 `REQUIRED`、`NESTED`）。

#### 2. **嵌套事务与 `PROPAGATION_NEVER` 冲突**
• **原因**：如果内层方法设置 `PROPAGATION_NEVER`，但外层有事务，会抛出异常。
• **示例**：
  ```java
  @Transactional(propagation = Propagation.REQUIRED)
  public void outer() {
      inner(); // inner 方法要求无事务 → 抛出 IllegalTransactionStateException
  }

  @Transactional(propagation = Propagation.NEVER)
  public void inner() {
      // ...
  }
  ```

---

### **五、多线程环境**
#### 1. **新线程中调用事务方法**
• **原因**：新线程的数据库连接与主线程不同，无法加入原事务。
• **示例**：
  ```java
  @Transactional
  public void mainMethod() {
      new Thread(() -> {
          transactionalMethod(); // 新线程事务独立！
      }).start();
  }
  ```
• **解决方案**：避免跨线程事务，或使用分布式事务框架。

---

### **六、其他场景**
#### 1. **非 `public` 方法使用 `@Transactional`**
• **原因**：Spring 仅对 `public` 方法生效，私有或包级方法会被忽略。
• **解决方案**：确保事务方法为 `public`。

#### 2. **编程式事务管理错误**
• **原因**：手动管理事务时未正确提交或回滚。
• **示例**：
  ```java
  @Autowired
  private PlatformTransactionManager transactionManager;

  public void doSomething() {
      TransactionStatus status = transactionManager.getTransaction(new DefaultTransactionDefinition());
      try {
          // 业务逻辑
          transactionManager.commit(status); // 必须显式提交
      } catch (Exception e) {
          transactionManager.rollback(status);
      }
  }
  ```

#### 3. **事务超时**
• **原因**：事务执行时间超过 `timeout` 设置，自动回滚。
• **解决方案**：调整超时时间：
  ```java
  @Transactional(timeout = 30) // 单位：秒
  ```

---

### **总结：事务失效的排查步骤**
1. **检查代理机制**：是否自调用？是否启用 `@EnableTransactionManagement`？
2. **检查异常处理**：是否捕获异常未抛出？是否配置 `rollbackFor`？
3. **检查数据库配置**：引擎是否支持事务？是否关闭自动提交？
4. **检查传播行为**：是否符合业务预期？
5. **检查线程模型**：是否跨线程调用？

通过以上场景分析和解决方案，可以系统性定位和修复 Spring 事务失效问题。
