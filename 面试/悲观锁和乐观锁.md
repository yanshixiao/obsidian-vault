**乐观锁与悲观锁** 是两种处理并发数据访问的策略，核心区别在于对冲突的预期和处理方式。以下从原理、实现方式到应用场景的全面解析：

---

### **一、核心思想对比**
| **锁类型** | **核心假设**               | **适用场景**                 | **实现方式**                     |
|------------|----------------------------|------------------------------|----------------------------------|
| **悲观锁** | 认为并发冲突**频繁发生**，需提前加锁避免冲突 | 写操作多、竞争激烈（如支付系统） | 数据库行锁、`synchronized`、`ReentrantLock` |
| **乐观锁** | 认为并发冲突**较少发生**，更新时再检测冲突 | 读操作多、冲突少（如库存查询） | 版本号、CAS（Compare And Swap）  |

---

### **二、悲观锁实现方式**
#### **1. 数据库行级锁（SELECT FOR UPDATE）**
```sql
-- 事务中锁定某行数据，阻止其他事务修改
BEGIN;
SELECT * FROM products WHERE id = 1 FOR UPDATE;
-- 执行业务逻辑（如扣减库存）
UPDATE products SET stock = stock - 1 WHERE id = 1;
COMMIT;
```

#### **2. Java同步机制**
• **synchronized 关键字**  
  ```java
  public class Counter {
      private int count = 0;
      
      public synchronized void increment() {
          count++;
      }
  }
  ```

• **ReentrantLock 显式锁**  
  ```java
  public class Counter {
      private int count = 0;
      private final ReentrantLock lock = new ReentrantLock();
      
      public void increment() {
          lock.lock();
          try {
              count++;
          } finally {
              lock.unlock();
          }
      }
  }
  ```

---

### **三、乐观锁实现方式**
#### **1. 版本号机制**
• **数据库实现**  
  ```sql
  -- 表添加版本号字段
  ALTER TABLE products ADD version INT DEFAULT 0;

  -- 更新时检查版本号
  UPDATE products 
  SET stock = stock - 1, version = version + 1 
  WHERE id = 1 AND version = 1; -- 假设当前版本号为1
  ```
  • 若返回影响行数为0，表示数据已被修改，需重试或抛异常。

• **Java对象版本控制**  
  ```java
  public class Product {
      private int id;
      private int stock;
      private int version;
      // Getters and Setters
  }

  // 更新时检查版本
  public boolean updateProduct(Product product) {
      int currentVersion = product.getVersion();
      // 模拟数据库操作
      if (product.getVersion() == currentVersion) {
          product.setStock(product.getStock() - 1);
          product.setVersion(currentVersion + 1);
          return true;
      }
      return false;
  }
  ```

#### **2. CAS（Compare And Swap）原子操作**
• **Java Atomic 类**  
  ```java
  AtomicInteger atomicInt = new AtomicInteger(0);
  atomicInt.incrementAndGet(); // 原子性自增
  ```

• **手动实现CAS逻辑**  
  ```java
  public class CASExample {
      private volatile int value;

      public synchronized int getValue() {
          return value;
      }

      public boolean compareAndSet(int expectedValue, int newValue) {
          synchronized (this) {
              if (value == expectedValue) {
                  value = newValue;
                  return true;
              }
              return false;
          }
      }
  }
  ```

### **四、应用场景对比**
| **场景**               | **推荐锁类型** | **原因**                                                                 |
|------------------------|----------------|--------------------------------------------------------------------------|
| **高频写操作**          | 悲观锁         | 避免大量重试开销，直接加锁保证原子性                                      |
| **低频写、高频读**      | 乐观锁         | 减少锁竞争，提升吞吐量                                                    |
| **短事务**              | 乐观锁         | 冲突概率低，CAS或版本号机制高效                                            |
| **长事务（如转账）**    | 悲观锁         | 防止其他事务长时间干扰数据                                                 |
| **分布式系统**          | 乐观锁         | 减少跨节点锁协调，通常结合版本号（如ETag）实现                              |

---

### **五、优缺点总结**
| **锁类型** | **优点**                     | **缺点**                                  |
|------------|------------------------------|-------------------------------------------|
| **悲观锁** | 强一致性，避免冲突           | 高锁开销，降低并发性，可能死锁             |
| **乐观锁** | 高并发，无死锁风险           | 需处理重试逻辑，ABA问题（需版本号或时间戳） |

---

### **六、实战选择建议**
1. **优先乐观锁**：在冲突率低、追求高吞吐的场景（如电商库存）。
2. **谨慎使用悲观锁**：在事务复杂、数据强一致性要求高时（如金融系统）。
3. **结合业务重试**：乐观锁失败后，可结合指数退避策略重试：
   ```java
   int retries = 3;
   while (retries > 0) {
       if (updateWithOptimisticLock()) {
           break;
       }
       retries--;
       Thread.sleep(100); // 退避等待
   }
   ```

---

**总结**：乐观锁与悲观锁各有优劣，选择时需权衡**并发量、冲突频率、数据一致性要求**。理解其原理及实现方式，可显著提升系统性能和稳定性。
