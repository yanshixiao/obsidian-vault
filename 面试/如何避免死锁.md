要避免死锁，需要破坏其产生的四个必要条件之一。以下是常见的避免死锁的策略及具体实现方法：

---

### 一、死锁的四个必要条件
1. **互斥条件**（Mutual Exclusion）：资源不能被共享，只能独占。
2. **请求与保持条件**（Hold and Wait）：线程持有资源并请求新资源。
3. **不可剥夺条件**（No Preemption）：资源只能由持有者主动释放。
4. **循环等待条件**（Circular Wait）：多个线程形成资源请求的环形链。

---

### 二、避免死锁的核心策略
#### 1. **破坏循环等待条件：固定加锁顺序**
**原理**：所有线程按全局一致的顺序获取锁，消除循环等待的可能。

**示例**：
```java
public class FixedOrder {
    private final Object lockA = new Object();
    private final Object lockB = new Object();
    private final Object lockC = new Object();

    // 全局加锁顺序：A → B → C
    public void method1() {
        synchronized(lockA) {  // 按顺序先获取A
            synchronized(lockB) {  // 再获取B
                // 操作A和B
            }
        }
    }

    public void method2() {
        synchronized(lockA) {  // 必须按顺序先获取A
            synchronized(lockB) {  // 再获取B
                synchronized(lockC) {  // 最后获取C
                    // 操作B和C
                }
            }
        }
    }
}
```

**适用场景**：需要获取多个锁的代码块。

---

#### 2. **破坏请求与保持条件：一次性申请所有资源**
**原理**：线程在执行前一次性申请所有需要的资源，若无法全部获取则等待。

**示例**：
```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class AllocateAllResources {
    private final Lock lockA = new ReentrantLock();
    private final Lock lockB = new ReentrantLock();

    public void execute() {
        // 尝试一次性获取所有锁
        boolean gotA = false;
        boolean gotB = false;
        
        try {
            gotA = lockA.tryLock();      // 尝试获取A
            gotB = lockB.tryLock();     // 尝试获取B
            
            if (gotA && gotB) {
                // 成功获取所有锁，执行业务逻辑
                System.out.println("执行任务");
            } else {
                // 未能获取全部锁，放弃已获得的锁
                System.out.println("资源不足，放弃操作");
            }
        } finally {
            if (gotA) lockA.unlock();   // 释放A（如果已获取）
            if (gotB) lockB.unlock();  // 释放B（如果已获取）
        }
    }
}
```

**适用场景**：资源数量已知且可预分配。

---

#### 3. **破坏不可剥夺条件：允许抢占资源**
**原理**：通过超时机制或中断机制强制释放已持有的锁。

**示例**（使用`ReentrantLock`的`tryLock`）：
```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class TimeoutExample {
    private final Lock lockA = new ReentrantLock();
    private final Lock lockB = new ReentrantLock();

    public void execute() {
        while (true) {
            if (lockA.tryLock()) {         // 尝试获取lockA
                try {
                    if (lockB.tryLock(1, TimeUnit.SECONDS)) { // 尝试获取lockB（带超时）
                        try {
                            // 成功获取两把锁
                            return;
                        } finally {
                            lockB.unlock();
                        }
                    }
                } finally {
                    lockA.unlock();        // 释放lockA，避免死锁
                }
            }
            // 等待随机时间后重试
            try { Thread.sleep((long)(Math.random() * 1000)); } 
            catch (InterruptedException e) { /* 处理中断 */ }
        }
    }
}
```

**适用场景**：高并发且资源竞争激烈时。

---

#### 4. **减少锁的粒度**
**原理**：将大锁拆分为多个小锁，降低竞争概率。

**示例**（使用分段锁）：
```java
public class FineGrainedLock {
    private final Object[] locks = new Object[16];
    private final int[] resources = new int[16];

    public FineGrainedLock() {
        for (int i = 0; i < locks.length; i++) {
            locks[i] = new Object();
        }
    }

    public void update(int index) {
        synchronized(locks[index % 16]) {  // 仅锁住对应分段
            resources[index]++;
        }
    }
}
```

**适用场景**：需要对大量独立资源进行并发操作（如`ConcurrentHashMap`）。

### 三、实际开发中的最佳实践
#### 1. **避免嵌套锁**
- **反例**：
  ```java
  synchronized(lockA) {
      synchronized(lockB) {  // 嵌套锁容易引发死锁
          // ...
      }
  }
  ```

#### 2. **使用高级并发工具**
- 优先选择`java.util.concurrent`包中的工具类：
  ```java
  // 使用并发集合代替手动同步
  Map<String, String> map = new ConcurrentHashMap<>();

  // 使用CountDownLatch协调线程
  CountDownLatch latch = new CountDownLatch(2);
  ```

#### 3. **代码审查与测试**
- **静态分析工具**：使用FindBugs、SpotBugs检测潜在死锁。
- **动态测试**：通过压力测试（如JMeter）模拟高并发场景。

#### 4. **监控与诊断**
- **JStack**：生成线程转储文件分析锁状态：
  ```bash
  jstack <pid> > thread_dump.txt
  ```
- **VisualVM**：实时监控线程阻塞和锁竞争情况。

### 四、死锁检测示例代码
```java
public class DeadLockDetector {
    public static void main(String[] args) {
        Object lock1 = new Object();
        Object lock2 = new Object();

        new Thread(() -> {
            synchronized(lock1) {
                try { Thread.sleep(100); } 
                catch (InterruptedException e) {}
                synchronized(lock2) {  // 等待lock2
                    System.out.println("Thread1 acquired both locks");
                }
            }
        }).start();

        new Thread(() -> {
            synchronized(lock2) {
                try { Thread.sleep(100); } 
                catch (InterruptedException e) {}
                synchronized(lock1) {  // 等待lock1
                    System.out.println("Thread2 acquired both locks");
                }
            }
        }).start();
    }
}
```

**运行结果**：  
程序挂起，无输出（典型死锁）。

### 五、总结
| **策略**                | **实现方法**                            | **优点**                  | **缺点**                  |
|-------------------------|----------------------------------------|--------------------------|--------------------------|
| 固定加锁顺序            | 全局统一的锁获取顺序                   | 简单有效                 | 锁数量多时难以维护       |
| 一次性申请所有资源      | 预先获取所有需要的锁                   | 避免部分死锁             | 可能降低并发性能         |
| 超时/中断机制           | 使用`tryLock`或`lockInterruptibly`     | 灵活可控                 | 增加代码复杂度           |
| 减少锁粒度              | 分段锁、读写锁分离                     | 提高并发度               | 设计复杂度高             |

**核心原则**：  
1. 尽量减少同步代码块的范围  
2. 避免在持有一个锁时获取其他锁  
3. 优先使用无锁数据结构（如`AtomicInteger`）  
4. 使用`java.util.concurrent`高级工具类替代手动同步
