### **视图（View）的定义**
**视图是数据库中的虚拟表**，由一个或多个真实表（基表）的查询结果动态生成。  
- **不存储实际数据**：视图本身仅保存查询逻辑，数据来源于基表。  
- **动态更新**：基表数据变化时，视图查询结果同步更新。  
- **作用类似“查询模板”**：简化复杂查询、控制数据访问权限、统一数据逻辑。

---

### **视图的核心作用**
#### 1. **简化复杂查询**
   - 将多表关联、过滤条件等复杂操作封装为视图，后续直接调用。
   ```sql
   -- 创建视图：统计每个部门的员工数量
   CREATE VIEW department_employee_count AS
   SELECT d.department_name, COUNT(e.employee_id) AS employee_count
   FROM departments d
   LEFT JOIN employees e ON d.department_id = e.department_id
   GROUP BY d.department_name;

   -- 使用视图查询
   SELECT * FROM department_employee_count WHERE employee_count > 10;
   ```

#### 2. **数据安全与权限控制**
   - 隐藏敏感字段（如密码、薪资），仅暴露必要数据。
   ```sql
   -- 创建视图：仅暴露员工姓名和部门
   CREATE VIEW employee_public_info AS
   SELECT employee_name, department_name
   FROM employees e
   JOIN departments d ON e.department_id = d.department_id;

   -- 用户只能访问视图，无法查看基表的其他字段（如薪资）
   ```

#### 3. **逻辑独立性**
   - 基表结构变化时（如字段重命名），可通过调整视图保持上层应用不受影响。

---

### **视图的优缺点**
| **优点**                  | **缺点**                          |
|---------------------------|-----------------------------------|
| 简化复杂查询，提高开发效率 | 性能可能下降（复杂视图需动态计算） |
| 增强数据安全性            | 部分视图不可更新（如含聚合函数）   |
| 统一业务逻辑              | 过度使用会增加维护复杂度           |

---

### **视图的分类**
#### 1. **普通视图（Non-Materialized View）**
   - 仅存储查询逻辑，数据实时从基表获取。
   - **适用场景**：数据频繁变动，需实时反映最新结果。

#### 2. **物化视图（Materialized View）**
   - 存储查询结果的物理副本，定期刷新数据。
   - **适用场景**：复杂查询结果需要快速访问（如数据仓库）。
   ```sql
   -- Oracle示例：创建物化视图
   CREATE MATERIALIZED VIEW sales_summary
   REFRESH FAST ON COMMIT
   AS
   SELECT product_id, SUM(quantity) AS total_sold
   FROM sales
   GROUP BY product_id;
   ```

---

### **视图的更新限制**
视图能否更新取决于其定义：
1. **可更新视图**：  
   - 视图基于单表且不包含聚合函数、`DISTINCT`、`GROUP BY`等操作。
   - 更新操作会直接映射到基表。
   ```sql
   -- 可更新视图示例
   CREATE VIEW active_employees AS
   SELECT employee_id, name FROM employees WHERE status = 'active';

   -- 更新视图数据（实际更新基表employees）
   UPDATE active_employees SET name = 'Alice' WHERE employee_id = 101;
   ```

2. **不可更新视图**：  
   - 包含聚合函数（如`SUM`、`COUNT`）、多表`JOIN`、子查询等。
   ```sql
   -- 不可更新视图示例（含聚合）
   CREATE VIEW department_avg_salary AS
   SELECT department_id, AVG(salary) AS avg_salary
   FROM employees
   GROUP BY department_id;

   -- ❌ 以下操作将报错
   UPDATE department_avg_salary SET avg_salary = 10000 WHERE department_id = 1;
   ```

---

### **视图 vs. 临时表**
| **特性**         | **视图**                          | **临时表**                        |
|------------------|-----------------------------------|-----------------------------------|
| **存储方式**     | 虚拟表（仅逻辑定义）              | 物理表（存储临时数据）            |
| **生命周期**     | 永久存在（除非显式删除）          | 会话或事务结束后自动删除          |
| **更新能力**     | 部分可更新                        | 完全可更新                        |
| **性能**         | 依赖基表查询效率                  | 独立存储，查询更快                |
| **适用场景**     | 简化查询、权限控制                | 中间结果暂存、复杂计算分步处理    |

---

### **视图的使用建议**
1. **避免嵌套过深**：多层视图嵌套会降低可读性和性能。
2. **慎用聚合视图**：频繁访问的聚合数据可改用物化视图或缓存。
3. **明确权限**：通过视图限制敏感字段访问，而非直接开放基表权限。

---

### **总结**
视图是数据库中的重要抽象工具，通过封装查询逻辑实现简化开发、保障安全、统一逻辑的目标。合理使用视图可提升代码复用性，但需注意其性能影响和更新限制。在需要高性能或数据预计算的场景下，物化视图是更优选择。
