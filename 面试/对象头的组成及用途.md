Java 对象头（Object Header）是每个 Java 对象在内存中的元数据，用于存储 **对象运行时关键信息** 和 **类型元数据指针**。它的结构和作用直接影响 JVM 的 **内存管理**、**锁机制** 和 **垃圾回收**。以下是对象头的核心组成及其用途：

---

### **对象头结构（以 HotSpot 为例）**
对象头一般包含以下数据（具体实现可能因 JVM 版本和配置不同而略有差异）：

#### 1. **Mark Word**
• **用途**：存储对象运行时状态信息（如锁状态、哈希码、GC 分代年龄等）。  
• **长度**：32 位 JVM 占 **4 字节**，64 位 JVM 占 **8 字节**（默认开启指针压缩时可能更小）。  
• **动态结构**：Mark Word 的内容会随着对象状态的变化而改变（如无锁、偏向锁、轻量级锁、重量级锁）。  

**Mark Word 的典型布局（以 64 位 JVM 为例）**：  
| 对象状态              | Mark Word 结构（64 bits）                     |
|-----------------------|-----------------------------------------------|
| **无锁（Normal）**    | 哈希码（25 bits）\| 分代年龄（4 bits）\| 锁标志位（01） |
| **偏向锁（Biased）**  | 线程ID（54 bits）\| Epoch（2 bits）\| 锁标志位（01） |
| **轻量级锁（Lightweight）** | 指向栈中锁记录的指针（62 bits）\| 锁标志位（00） |
| **重量级锁（Heavyweight）** | 指向监视器（Monitor）的指针（62 bits）\| 锁标志位（10） |
| **GC 标记**           | 空（用于垃圾回收阶段）\| 锁标志位（11）           |

**关键字段说明**：  
• **哈希码（Identity HashCode）**：对象的唯一哈希值（调用 `hashCode()` 时生成）。  
• **分代年龄（Age）**：对象存活次数，用于新生代晋升老年代的阈值（默认 15）。  
• **锁标志位（Lock Flag）**：标识当前锁状态（如 `01` 无锁，`00` 轻量级锁等）。  
• **线程ID**：偏向锁持有的线程 ID。  
• **Monitor 指针**：重量级锁关联的监视器（操作系统互斥量）地址。  

---

#### 2. **Klass Pointer（类型指针）**
• **用途**：指向方法区（Metaspace）中的类元数据（`Klass` 对象），用于确定对象的类型。  
• **长度**：32 位 JVM 占 **4 字节**，64 位 JVM 占 **8 字节**（开启指针压缩时为 **4 字节**，通过 `-XX:+UseCompressedClassPointers` 控制）。  
• **示例**：通过该指针，JVM 可以知道对象属于哪个类，从而正确解析字段和方法。  

---

#### 3. **数组长度（Array Length，仅数组对象存在）**
• **用途**：记录数组的长度（如 `int[]` 或 `String[]`）。  
• **长度**：占 **4 字节**。  
• **作用**：JVM 通过该字段检查数组访问是否越界（如 `ArrayIndexOutOfBoundsException`）。  

---

### **对象头完整布局示例**
以 **普通对象**（非数组）在 64 位 JVM（开启指针压缩）为例：  
```
| Mark Word (8 bytes) | Klass Pointer (4 bytes) | 对齐填充 (可选) |
```
以 **数组对象** 为例：  
```
| Mark Word (8 bytes) | Klass Pointer (4 bytes) | 数组长度 (4 bytes) | 对齐填充 (可选) |
```

---

### **对象头的作用**
1. **锁机制（Synchronized）**  
   • 通过 Mark Word 的锁标志位实现 **偏向锁**、**轻量级锁**、**重量级锁** 的升级与降级。  
   • 例如：  
     ◦ **偏向锁**：直接记录线程 ID，避免 CAS 操作。  
     ◦ **轻量级锁**：通过栈帧中的锁记录（Lock Record）实现自旋等待。  
     ◦ **重量级锁**：关联操作系统互斥量（Monitor），线程进入阻塞状态。  

2. **垃圾回收（GC）**  
   • 通过 Mark Word 中的分代年龄（Age）判断对象是否应晋升到老年代。  
   • 在 GC 过程中，通过锁标志位判断对象是否存活（如标记阶段）。  

3. **对象哈希码（HashCode）**  
   • 首次调用 `hashCode()` 时生成并存储到 Mark Word 中。  
   • 如果对象已处于加锁状态（如轻量级锁），哈希码会被移动到锁记录中。  

4. **类型信息**  
   • Klass Pointer 指向方法区中的类元数据，支持动态方法调用（如虚方法表）。

### **查看对象头（实验工具）**
可以使用 **JOL（Java Object Layout）工具** 分析对象头：  
```java
// 添加 Maven 依赖：org.openjdk.jol:jol-core
public class ObjectHeaderDemo {
    public static void main(String[] args) {
        Object obj = new Object();
        System.out.println(ClassLayout.parseInstance(obj).toPrintable());
    }
}
```
**输出示例**：  
```
java.lang.Object object internals:
OFF  SZ   TYPE DESCRIPTION               VALUE
  0   8        (object header: mark)     0x0000000000000001 (non-biasable; age: 0)
  8   4        (object header: class)    0x200001e5
 12   4        (alignment/padding gap)   
Instance size: 16 bytes
```

### **优化建议**
1. **减少锁竞争**：避免不必要的同步，优先使用无锁结构（如 `ConcurrentHashMap`）。  
2. **控制对象大小**：避免过多小对象（对象头占用比例高），合理使用基本类型数组。  
3. **指针压缩**：在 64 位 JVM 中开启 `-XX:+UseCompressedOops` 和 `-XX:+UseCompressedClassPointers` 减少内存占用。  

---

### 总结
Java 对象头是 JVM 管理对象生命周期的核心数据结构，理解其组成和用途对优化 **内存使用**、**锁性能** 和 **GC 效率** 至关重要。通过工具（如 JOL）结合实践，可以深入掌握对象在内存中的真实布局。
